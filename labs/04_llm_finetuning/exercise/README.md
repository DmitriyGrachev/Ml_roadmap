# Самостоятельный опыт адаптации формата ответа

Сначала закончите [HF lab](../../02_huggingface_models/README.md) и её
оценку на фиксированном test split. Затем прочитайте [теорию](../theory.md).
Здесь другая задача: модель должна отвечать в согласованном формате на разрешённых
синтетических описаниях предметов. Готового trainer и заполненного отчёта нет.

Вы сами определяете небольшую схему ответа, разрешённый корпус и неоднозначные
случаи, а также группы перефразировок, которые не могут попадать в разные split.
Не используйте пользовательские документы, переписки или секреты. До обучения
зафиксируйте тестовые примеры и критерии: соответствие формату, правильность
значений, отказы на неподдержанной задаче, типы ухудшений.

## Три сравнимых варианта

1. Исходная выбранная небольшая модель без обучения.
2. Та же модель с улучшенным prompt, выбранным по validation, не по test.
3. Та же база с LoRA и зафиксированным template/config; исходная база сохранена.

Одинаковыми остаются test IDs, генерационные ограничения и правила оценки.
Различия входной инструкции/адаптации записываются. Данные для обучения не должны
содержать ответы test. Если честного улучшения нет, это допустимый результат.

Проверьте до обучения: хотя бы один target token в каждом используемом примере,
правильные padding/loss masks, внутренний causal shift, названия target modules,
какие параметры trainable. Начните без packing. QLoRA не обязательна для этого опыта.

## Что сохранять

Новый каталог запуска: версии/seed/config, revision и digest базы/tokenizer,
data/split identity, adapter bytes, predictions всех трёх вариантов, пересчитанные
metrics, ошибки и наблюдаемые время/память. Отдельно сохраните вывод проверки
fresh-base reload: та же база + сохранённый адаптер должны воспроизводить
оговорённые предсказания при зафиксированном режиме.

Следуйте [общему протоколу](../../../docs/experiment-protocol.md); не подставляйте
teacher-algebra JSON вместо языкового эксперимента. Не ставьте непроверенные
значения памяти, latency или метрик. Если GPU/run недоступны, пишите NOT_RUN.

Реальная установка PEFT, выбор/download базы и обучение — отдельные явные действия.
Пока они не выполнены, этот опыт не считается завершённым. Базовые
`pytest labs/04_llm_finetuning/test_demo.py` проверяют только teacher mechanism.
Существующие CLI ID, `test/check` и progress не меняются.

## Защита

Покажите одну удачную и одну неудачную новую формулировку, которой не было при
настройке. Объясните, почему решили менять weights, а не только prompt/retrieval,
как считали качество, где стало хуже и как восстановить baseline. Самостоятельные
графики сопровождайте вопросом, наблюдением и тем, чего график не доказывает.
