# От источника до accepted row

Все 21 текста [data.json](data.json) написаны для этого teacher примера.
[sources.json](sources.json) разрешает CC0-1.0 именно на эти тексты и аннотации;
внешние документы, персональные сведения и чужие datasets не использовались.
Это запись происхождения, не автоматическое юридическое заключение о любом другом источнике.

Единица наблюдения — описание одного предмета. `source_id=author-shapes-v1`
указывает происхождение; `group_id` — партия предметов, которая остаётся в одном split.
`row_id` сохраняет identity строки; content hash отдельно обнаруживает изменение текста.

| Текст | Статус | Решение и причина |
| --- | --- | --- |
| `red small circle` (s01) | accepted | `circle`: ровно одна явно названная фигура |
| `blue large triangle object` (s21) | accepted | `triangle`: цвет, размер, порядок слов не меняют label |
| `red circle square` | review, вне data | Две фигуры; запросить уточнение, не выбирать первую молча |
| `large green object` | review, вне data | Фигура не названа; не выводить её из цвета |
| `blue circl` | rejected, вне data | Опечатка вне принятого словаря; исправление требует новой версии |
| Пустой текст | rejected, вне data | Не описание; нельзя считать четвёртым классом |

Аннотатор читает текст, называет единственную фигуру и записывает label из ordered
`circle,square,triangle`. Второй просмотр сверяет правило, не prediction baseline.
Неоднозначные примеры выше не входят ни в train, ни в evaluation и не имеют
выдуманного ground truth. Нормализация для leakage не исправляет орфографию.

[splits.json](splits.json) зафиксирован до обучения:

| Split | IDs | Groups | Label counts circle / square / triangle |
| --- | --- | --- | --- |
| train | s01–s12 | lot-train-1…4 | 4 / 4 / 4 |
| validation | s13–s15 | lot-validation | 1 / 1 / 1 |
| test | s16–s21 | lot-test-1…2 | 2 / 2 / 2 |

Каждая партия целиком в одной строке таблицы. После чтения test ошибки не меняйте
правила этого run. Новая гипотеза требует нового заранее сформулированного study.
Даже group-disjoint split здесь использует повторяющиеся формы коротких описаний:
это намеренное упрощение для save/reload, не оценка переноса на новые шаблоны.
