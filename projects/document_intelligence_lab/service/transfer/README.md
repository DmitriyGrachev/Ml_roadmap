# Самостоятельный перенос своей A1 модели

Вход: завершённый собственный A1 bundle и backend prerequisites из
[service README](../README.md). Учительский `prepare-teacher` не является вашим результатом.

Выберите абсолютный путь к **своему** bundle и отдельно сохранённый проверенный
manifest digest. Напишите собственный операторский config из двух полей
`bundle_root` и `expected_manifest_sha256`. Защитите config и каталог от подмены.
Не передавайте их в HTTP запрос. Для известного локального sklearn pickle
обоснуйте доверие и используйте явный startup флаг.

До запуска предскажите ответы для обычного текста, пробельного текста и одного
пограничного случая вашего домена. Сверьте offline inference и API на фиксированных
своих test IDs. Сохраните результаты в новом собственном output. Затем создайте
копию bundle с испорченными байтами: объясните отказ и восстановите исходный
полный комплект после нового запуска. Не меняйте исходные test данные для
получения лучшего результата. Сначала определите expected поведение без вызова API.

Независимая вариация: изменилось правило допустимого размера документа или
появился новый класс. Выберите **одно**, объясните, где потребуется новая версия,
почему старый bundle несовместим или совместим, и какие проверки это обнаружат.
Не копируйте shape labels или teacher error analysis в свой домен.

Заполните копию [пустого report template](report-template.md) только собственными
наблюдениями. Проверка преподавателем: независимый bundle/config, actual bytes,
offline/API parity, invalid input, отказ startup, fresh restart A и объяснение
ошибок. Автозачёта/catalog ID для этого transfer нет; существующие ID и student
TODO не менялись. Container и MLflow помечайте NOT_RUN до реального разрешённого запуска.
