# Две задачи, одна управляемая система

Представьте архив: входящие документы нужно распределять по категориям, а на
вопросы о правилах архива — отвечать по разрешённым источникам. Первая задача
возвращает метку, вторая — доказуемый фрагмент ответа либо отсутствие ответа.
Один удачный классификатор не означает, что система правильно цитирует правила.

Prerequisites: [часть A](part_a/README.md), [часть B](part_b/README.md),
[bounded workflows](../../modules/07_agents/01_workflows_state/README.md),
[production product study](../../modules/08_production_ai/exercises/product_study/README.md),
[serving](../../labs/05_model_serving/README.md) и
[lifecycle](../../labs/06_ml_lifecycle/README.md). Не заменяйте эти работы интеграционным demo.

```text
                       доверенная конфигурация оператора
                         |                    |
входной документ → saved classifier        права пользователя
                         |                    |
                    метка + model ID       фильтр ACL
                                              |
вопрос → retrieval по разрешённым sources → ограниченный контекст
                                              |
                                  выбранный provider → проверка выхода
                                              |
                                   answer + citations / no-answer

недоверенные документы НЕ изменяют права, tools, budget или конфигурацию
```

Метка классификатора — прогноз, а не разрешение доступа (**authorization**).
Даже если модель назвала запрос «служебным», она не предоставляет ему роль staff.
Источники имеют version/source ID и действующие права до top-k и перед передачей
контекста. Citation связывает текст с источником, но сама не доказывает истинность
утверждения. Проверьте, поддерживает ли приведённый фрагмент именно этот вывод.

## Небольшой разбор: сначала ограниченная последовательность

```powershell
.venv/Scripts/python.exe -m projects.document_intelligence_lab.integration_demo --output artifacts/document-integration-001
.venv/Scripts/python.exe -m pytest projects/document_intelligence_lab/tests -q
```

Каталог должен быть новым. Пример вызывает уже существующие A1, CPU service и
teacher Real RAG, а не создаёт три новые реализации. Он делает один classifier
запрос и пять фиксированных retrieval сценариев. Нет циклов рассуждения, retries,
выполнения shell-команд, внешних запросов или загрузки модели.

| Шаг | Вход/операция | Проверяемое наблюдение |
| --- | --- | --- |
| 1 | Сохранённый TF-IDF → `/predict` для `small blue triangle` | `triangle`; ответ содержит точный bundle identity |
| 2 | `scanner settings`, public role | Выдержка разрешённого источника с citation |
| 3 | Тот же вопрос, provider намеренно недоступен | `provider_error`, а не выдуманный ответ |
| 4 | Старые candidates, актуальный corpus пуст после удаления | `no_answer`; удалённый текст не попадает в контекст |
| 5 | `cabinet code`, по-прежнему public role | `no_answer`; classifier не повышает права |
| 6 | `volcano insurance`, источника нет | `no_answer`, не ответ из памяти модели |

Answer demo возвращает **детерминированную выдержку**, не ответ LLM. `llm_generation`
и Qdrant/vLLM в отчёте остаются `NOT_RUN`; `answer_quality=REQUIRES_REVIEW`.
Фиксированные вызовы проверяют композицию и отказы, не способность к сложному диалогу.
Произвольный синхронный provider нельзя прервать этим demo: реальный adapter обязан
ограничивать время/bytes и прекращать запрос, как разбирается в serving lab.

Типичная ошибка — свести classification accuracy, Recall@k и долю поддержанных
ответов в одно «AI accuracy». Это разные знаменатели и виды ошибки. В demo
`combined_ai_accuracy=null` намеренно: такого показателя без постановки нет.

## Выбор сложности под требование

| Ограничение или вопрос | С чего начать | Когда усложнять / что пока отвергнуть |
| --- | --- | --- |
| Метки хорошо отделяются словами | Rules/TF-IDF baseline | Encoder после общей оценки и разбора ошибок, не из-за популярности |
| Значение зависит от контекста и формулировок | Сравнение с pretrained encoder | Fine-tuning только с данными и отдельным held-out protocol |
| Ответ зависит от свежего источника | Retrieval с версиями и permissions | Изменение весов не заменяет актуальный документ |
| Вопросов мало, результат нужен завтра | Batch | Постоянный API/GPU не обязателен |
| Ответ нужен интерактивно | Один ограниченный API, deadline и backpressure | Несколько сервисов только после измеренного узкого места |
| Нельзя отправлять тексты наружу | Рассмотреть локальный inference/обезличивание/отказ | Self-host требует эксплуатации; API требует условий обработки данных |
| Процесс имеет известные шаги | Явная конечная последовательность | Автономный агент не нужен для вызова двух функций |
| RTX 5060, ограниченная VRAM | Малые модели, короткий context, последовательные jobs | Не обещать одновременное embedding + generation + training на 8 GB |

Baseline comparison — эксперимент, не голосование за более сложную технологию.
Стоимость включает память, время оператора, восстановление и ошибки, не только
цену одного токена. Облако выбирается в [отдельном launch gate](deployment/README.md).

## Самостоятельная система и приёмка

Соберите свой проект после предыдущих заданий. Используйте свои разрешённые данные
и другие вопросы, не копируйте teacher artifacts как портфолио. Сначала запишите
требования, acceptance cases и бюджет; только затем выбирайте инструменты.

| Проверка | Что сохраняет ученик | Что должно быть объяснено |
| --- | --- | --- |
| Classification errors | Fixed test IDs, predictions, confusion, ошибки по группам | Где baseline лучше; размер/ограничение выборки |
| Retrieval | Fixed queries/judgments, ranking, Recall/MRR по постановке | Почему потерян релевантный источник; сравнение lexical/dense |
| Answer | Ответы, citations, ручная рубрика, unsupported/no-answer cases | Чем цитирование отличается от поддержки утверждения |
| Permissions и prompt injection | Разрешённые/запрещённые роли, traces без секретов | Почему данные не становятся инструкцией и права не задаются LLM |
| Update/delete/stale | Старый/новый manifest и повтор старых вопросов | Почему удалённый источник действительно перестал использоваться |
| Outage/cancellation/budget | Реальные ограничения и результаты отказов | Что пользователь видит при отказе, почему нет бесконечного retry |
| Restart/rollback | Восстановленные bytes, модель/preprocessing/index, повтор outputs | Совместимость полного release, а не смена одного имени |

[Service recovery](service/README.md) и [lifecycle](../../labs/06_ml_lifecycle/README.md)
дают механизмы и малые демонстрации; они не являются вашим incident report.
Используйте [структуру защиты](defense-template.md) и существующую
[rubric](../../docs/project-defense.md). Не заполняйте NOT_RUN вымышленными цифрами.

Вариация для защиты: завтра часть источников становится доступна только staff,
а latency budget уменьшается вдвое. Какие artifacts/проверки нужно повторить?
Почему смены prompt недостаточно? Какой компонент вы уберёте первым и почему?
