# Готовность к самостоятельной ML-работе: рубрика защиты

Эта рубрика отделяет исправность учебного кода от способности решить новую задачу.
Тесты проверяют поведение, происхождение артефактов и воспроизводимую арифметику.
Они не определяют авторство, качество постановки задачи и глубину объяснения.
Итоговый статус без обсуждения с человеком — **REQUIRES_REVIEW**.

## Три вида доказательств

| Статус | Что предъявить | Что он означает |
|---|---|---|
| Техническая проверка | `check ID` / `check-track`, код, тесты, воспроизводимые артефакты | Контракты выполнены; required skip/xfail не скрыт |
| Реальный эксперимент | Внешние данные и их hash, команды, версии, split IDs, реальные predictions/checkpoints, журнал ошибок | На указанных данных и в указанной среде эксперимент действительно можно воспроизвести |
| Содержательная защита | Объяснение решений, разбор ошибочного подхода, изменение задачи без готового шаблона | Ученик понимает ограничения и переносит метод на новую ситуацию |

Сохраняйте свою запись защиты вне шаблонов репозитория. Для каждого критерия:
`не показано`, `частично`, `самостоятельно`, ссылки на конкретные файлы/наблюдения,
имя проверяющего и дату. Не складывайте пункты в искусственный «процент готовности»:
ошибка утечки или отсутствующий baseline не компенсируется красивым API.

## Что защищать

| Область | Слабое объяснение | Сильное доказательство | Задание на перенос |
|---|---|---|---|
| Постановка | «Нужен AI, обучил классификатор» | Кто использует прогноз, когда доступны признаки, цена false positive/negative, простой baseline и причина использовать модель | Предложить правило, при котором ML пока не нужен, и эксперимент, меняющий это решение |
| Данные и split | «Поставил random_state=42» | Происхождение и лицензия, unit of analysis, train/dev/test IDs; entity/time ограничения; preprocessing fit только на train | Добавить повторные наблюдения одного пользователя или временной сдвиг и пересмотреть split |
| Метрики | «Accuracy 95%, значит хорошо» | Baseline, распределение классов, confusion matrix, PR/ROC и порог на dev, срезы ошибок, ограничения metric | Увеличить цену пропуска редкого класса, выбрать новый threshold без подсматривания test |
| Математика | «Градиент считает autograd» | Вывод MSE/BCE при объявленной редукции, bias/L2, finite-difference проверка; геометрия Ridge; шаги дерева/boosting | Изменить веса наблюдений, масштаб признака или знак остатка и предсказать эффект до запуска |
| Статистика | «На одном seed лучше на 0.01» | Парное сравнение на тех же строках, интервал условно на фиксированных моделях, отдельно повторные полные обучения | Показать, как вывод меняется при меньшей выборке, group/time split и неустойчивой оптимизации |
| Python | «Переписал Java-класс» | Идиоматичные структуры, typed API, wheel работает вне checkout, один transform для train/serve | Добавить несовместимый вход, проверить clear failure и сохранение поведения API |
| Async | «gather запускает параллельно» | Bounded concurrency, timeout, cancel, cleanup; нет фоновых orphan tasks; понимание blocking I/O/CPU | Отменить родительскую задачу во время запроса и проверить освобождение ресурсов |
| Pretrained NLP | «Transformer сложнее, значит лучше» | TF-IDF/frozen/adapted на одном внешнем split; модель и tokenizer pin; compute, macro-F1/срезы, ошибки | Сменить домен/длину текста и объяснить, когда адаптация проигрывает baseline |
| RAG | «Векторная база нашла документ» | Retrieval отдельно от answer quality; masked pooling; dev/holdout; ACL/stale/no-answer/ambiguity; подтверждённые ссылки | Удалить ответ из корпуса, закрыть доступ или добавить конфликтующие версии и оценить отказ |
| Delivery | «FastAPI TestClient прошёл» | Сохранённая модель, реальные TCP-запросы, concurrency/timeouts, cold/warm latency, restart/rollback, версии | Повредить новую модель, перезапустить сервис и восстановить прежнюю версию без ложной готовности |
| Data pipeline | «Скрипт один раз создал CSV» | SQL extraction, idempotency, поздние/повторные/невалидные строки, manifest/hash, повторяемый replay | Повторить batch, доставить позднее событие и объяснить, почему результат не удвоился |
| Мониторинг | «Следим за drift» | Отдельно schema/data drift, latency/errors и качество с задержкой labels; понятные действия/rollback | Смоделировать drift без ухудшения модели и ухудшение без явного drift |

## Как провести защиту двух внешних проектов

Технический PASS этих проектов проверяет реальные сохранённые артефакты и model
replay. Реализация предложенных `run_experiment`/`run_study`, самостоятельность
runner и независимый clean rerun проверяются на защите: artifact gate эти функции
не вызывает. Допустим самостоятельно написанный альтернативный entry point с тем
же воспроизводимым протоколом и сохранёнными исходниками/командой запуска.

1. Проверяющий выбирает commit, удаляет только воспроизводимые generated outputs
   в собственной временной копии и запускает инструкции. Исходные данные сверяются
   по hash. Нельзя требовать доступ к секретам или чужим клиентским данным.
2. Ученик объясняет split, feature availability и baseline до показа итоговой метрики.
   Проверяющий выбирает несколько row IDs и прослеживает их от raw данных до prediction.
3. Обсуждаются минимум несколько реальных ошибок разных типов, включая ошибки
   лучшей модели. Небольшая или отрицательная разница с baseline допустима, если
   эксперимент корректен; «обязательного хорошего score» нет.
4. Проверяющий предлагает одну модификацию из таблицы. Ученик сначала прогнозирует
   последствия, затем меняет код/эксперимент и сравнивает наблюдение с ожиданием.
5. Итог фиксируется по критериям. При существенной утечке, неотделённом test,
   несовместимом preprocessing или невоспроизводимом эксперименте проект дорабатывается.

## Что можно предъявлять работодателю

README с постановкой, данными и ограничениями; команды запуска; содержательный
experiment log; воспроизводимый pipeline; API и измерения; несколько решений,
которые оказались неудачными, и объяснение почему. Если cloud/GPU/container не
запускались, так и указать. Локальный TCP harness — свидетельство локальной
эксплуатационной практики, а не многомесячной production-работы.

После самостоятельной защиты core и двух внешних проектов разумно начинать
проверять себя на подходящих интервью и небольших прикладных задачах. Требования
стажа, языка, образования и страны проверяются по конкретной вакансии. Продолжать
весь список необязательных технологий перед первым откликом не требуется.

## Прикладной NLP и инструменты PA1

Дополнительно защитить независимые результаты из [карты практики](applied-tools-practice.md):

- Объяснить обработку масок/оси NumPy, временную доступность Pandas-признаков и group-CV preprocessing.
- Перенести ручной training loop в Trainer, проверить collator, best checkpoint и resume.
- Обосновать NER subword labels, BIO spans и судьбу обрезанных entities; показать другой домен.
- В SFT показать реальные train masks, frozen base/adapter, общий holdout base/prompt/LoRA и reload.
- Разделить candidate recall и качество reranking; объяснить false negatives при embedding adaptation.
- Восстановить выбранный MLflow/Optuna эксперимент и показать, что holdout не участвовал в подборе.
- Для vLLM показать actual runtime/restart и raw measurement arithmetic; для GPU/QLoRA честно
  оставить NOT_RUN, если опыт ещё не выполнен.

Автоматические evidence checks сверяют структуры, артефакты и вычисления. Оценка
авторства, нового домена и обоснованности решения остаётся человеческой.
