# Шаблон теоретического урока

Компактная редакционная памятка, не новый формат CLI и не автоматический зачёт.
Пилот: [Object Model](../modules/01_python_core/01_object_model/README.md).
Сохраняйте существующие ID, порядок, контракты упражнений и progress.

## Каркас

1. **Зачем и что уже нужно знать.** Одна конкретная задача, результат понимания,
   ссылки на реальные prerequisites. Не требуйте будущий урок для чтения текущего.
2. **Ситуация и прогноз.** Маленький нейтральный пример и вопрос до объяснения.
   Минимально необходимый синтаксис объясните на месте.
3. **Интуиция.** Сначала словами опишите механизм; затем схема или иной уместный
   образ. Укажите границы аналогии, а не выдавайте её за устройство системы.
4. **Точность.** После примера введите определения с английскими эквивалентами.
   Аналогию с Java сопровождайте различиями; не считайте знакомый язык доказательством.
5. **Разобранная демонстрация.** Код → состояния/промежуточные результаты →
   полный ожидаемый вывод → причина → одна изменённая строка → типичная ошибка.
   Демонстрация завершена; существующие student TODO остаются самостоятельными.
6. **Активное понимание.** 2–3 прогноза по ходу, затем 5–7 вопросов. Ответы можно
   скрыть до попытки. Результат: объяснить новый пример, а не повторить формулировку.
7. **Перенос в практику.** Ссылки на подходящие существующие задания и их ID,
   с prerequisites и объяснением, что именно там применяется. Не давать решение.
8. **Источники и остановка.** Немного точных разделов: автор, название, URL,
   язык, зачем читать и где остановиться. Указать дату/способ проверки и ограничения.

## Для математических тем, только когда уместно

- Расшифровать каждый символ, формы массивов и единицы измерения.
- Показать одну ручную подстановку со всеми промежуточными результатами.
- Связать каждый существенный шаг формулы с кодом.
- Подписать оси графика, диапазоны и сделанные упрощения.
- Дать эксперимент «изменить параметр → предсказать → проверить».
- Назвать границы применимости и разобрать типичную ошибку.
- `visual.ipynb` с графиками/опциональными виджетами допустим лишь при реальной
  учебной пользе; для текущего пилота не создаётся, зависимости не добавляются.

## Проверка автора

Переиспользуйте существующий пример; README остаётся входом. SVG или другой
локальный формат должен иметь подписи, текстовую альтернативу и читаться
без сетевых шрифтов/скриптов. Каждая стрелка или точка соответствует коду.
Проверьте реальный запуск, выводы, переходы и отображение, полезные поведенческие
тесты и принятые lint/type checks. Запишите команды, среду и ограничения;
непроведённое обозначайте NOT_RUN/NOT_VERIFIED. Не приравнивайте проверку файла
к пониманию ученика и не меняйте progress за него. Не отправляйте его код внешним сервисам.

Исторически следующими после пилота были NumPy и математический мост. Их материалы,
как и теоретические пакеты 1–7, уже подготовлены: см. [актуальный аудит покрытия](wave2-coverage.md#route-integration-audit).
Не реализуйте их повторно. Оставшиеся дополнения по этому шаблону перечислены
в [едином плане](superpowers/plans/2026-10-11-remaining-roadmap.md); готовность текста
по-прежнему не означает освоение учеником или выполненный модельный эксперимент.
