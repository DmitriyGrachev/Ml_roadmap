# First control flow: count labels

ID: `python-control-flow`. Начальный уровень, 20–35 минут.
Перед началом: [первые строки Python](../basics.md). Продвинутые коллекции не нужны.

В `starter.py` реализуйте `count_long_labels(labels, minimum)`:

- `labels` — именно список строк; `minimum` — целое число ≥ 1, `bool` не принимается.
- Проверить все входы; при нарушении выбросить `ValueError`, даже если список пуст.
  В сообщении указать `minimum` для неверного порога, `labels` для неверного списка/элемента.
- Считать строки, у которых после удаления внешних пробелов длина **не меньше** minimum.
- Пустые/пробельные строки не считать, пустой список даёт 0.
- Список не менять, каждый вызов начинает накопление заново.

`raise ValueError("причина")` останавливает вызов с ошибкой вместо неверного результата.
`type(minimum) is int` отличает целое от `bool`; `isinstance(label, str)` проверяет
строку. Это минимальная проверка входа, полный разбор исключений будет позже.

Сначала на бумаге предскажите результат для `["  sky ", "a", ""]`, minimum=3,
затем напишите свою функцию. Не заполняйте тесты ожидаемыми значениями, вычисленными
этой же функцией: они должны быть известны независимо.

Из корня:

```powershell
uv run python scripts/learn.py test python-control-flow
uv run python scripts/learn.py check python-control-flow
```

`test` проверяет инфраструктуру, TODO даст xfail. `check` — строгий зачёт только
этого задания, xfail/skip недопустимы. Тесты не меняют progress. Когда изучите pytest,
добавьте собственный boundary case. Устная защита: проследите счётчик по шагам,
объясните остановку цикла, различие return/print и почему проверка minimum идёт
даже для пустого списка. Зелёные tests не заменяют это объяснение.
