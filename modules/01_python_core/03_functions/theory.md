# Functions: передавать действие как значение

[Вход и задания](README.md) · [Запускаемый пример](example.py)

## 1. Зачем это нужно и первый прогноз

Отправка уведомления знает сообщение, но оформление текста может выбирать вызывающий код. В [example.py](example.py) `notify` получает `formatter` и применяет его. Прогноз № 1: что изменится, если передать `formatter("document indexed")` вместо `formatter`? Запишите, будет ли внутри `notify` ещё что-то вызываемое.

Предпосылки — [Object Model](../01_object_model/README.md) и [Collections](../02_collections/README.md). Функция тоже объект: её можно связать с именем, передать аргументом и вернуть как результат. Короткая Java-аналогия — объект, реализующий функциональный интерфейс; в Python ради каждого callback не объявляют отдельный интерфейс. Это сходство назначения, а не совпадение правил связывания аргументов.

## 2. `notify`: значение функции и результат вызова

**Параметр (parameter)** — имя в определении функции; **аргумент (argument)** — переданное при вызове значение. **Callback** — функция, которую передают другой функции для последующего вызова. Выражение `formatter` получает объект функции. Скобки `formatter(message)` запускают вызов и дают его результат. Если ожидался callback, преждевременный вызов подменяет действие результатом.

В существующем файле `Notifier = Callable[[str], str]` описывает намерение: вызываемое значение принимает строку и возвращает строку. Эта подсказка типа не запускает проверку сама по себе. `notify(message, formatter)` возвращает результат `formatter(message)`. `main()` передаёт строку и `lambda message: f"NOTICE: {message}"`; `lambda` — короткое выражение функции. Именованная функция предпочтительнее, когда логика разрастается или у неё есть важное деловое имя.

<a id="example"></a>

| Момент | Связанные значения | Действие |
| --- | --- | --- |
| До `notify` | первый аргумент — строка `"document indexed"`; второй — объект lambda | Функция ещё не оформляла сообщение |
| Вход в `notify` | локальный `message` связан с той же строкой; локальный `formatter` — с lambda | Аргументы привязаны к параметрам |
| `formatter(message)` | lambda получает строку | Возвращает `"NOTICE: document indexed"` |
| Выход из `notify` | `return` передаёт строку `main()` | `print` выводит её |

Из корня репозитория запустите существующий пример:

```powershell
uv run --offline --no-sync python modules/01_python_core/03_functions/example.py
```

Самодостаточная проверка того же файла:

```pycon
>>> import runpy
>>> runpy.run_path("modules/01_python_core/03_functions/example.py", run_name="__main__") and None
NOTICE: document indexed
```

Это полный вывод. Ответ на прогноз: `formatter("document indexed")` вызовет оформление **до** `notify` и передаст строку вместо функции. Тогда попытка `formatter(message)` внутри приведёт к `TypeError`, если передано именно это строковое значение. Не путайте возможность передавать функции со способностью вызывать любое значение.

## 3. Как вызов связывает аргументы

По умолчанию параметр можно заполнить позицией или именем. В **сигнатуре (signature)** `/` отделяет **позиционные-only (positional-only)** параметры: слева можно передать только по позиции. Отдельная `*` начинает **именованные-only (keyword-only)** параметры: справа нужны имена. Между ними параметры допускают оба способа. Это правила публичного вызова, а не операторы деления или умножения.

```pycon
>>> def label(text, /, prefix="DOC", *, upper=False):
...     result = f"{prefix}:{text}"
...     return result.upper() if upper else result
>>> label("draft", upper=True)
'DOC:DRAFT'
>>> label("draft", prefix="NOTE")
'NOTE:draft'
```

В первом вызове `"draft"` заполняет `text` по позиции, `upper=True` — только по имени, `prefix` берётся из значения по умолчанию. Во втором `prefix` заполнен именем. Вызов `label(text="draft")` был бы ошибкой связывания, потому что `text` находится слева от `/`.

Другая роль звёздочек — сбор лишних аргументов. `*args` собирает дополнительные позиционные аргументы в **кортеж (tuple)**, а `**kwargs` собирает дополнительные именованные аргументы в **словарь (dict)**. Имена `args`/`kwargs` условны; важны маркеры. Не превращайте их в обязательный шаблон каждой функции: явные параметры читаются лучше, когда интерфейс известен.

```pycon
>>> def inspect(prefix, *args, **kwargs):
...     return prefix, args, kwargs
>>> inspect("doc", 2, 3, language="en")
('doc', (2, 3), {'language': 'en'})
```

В сигнатуре звёздочки **collect**; в месте вызова те же маркеры **unpack** последовательность/отображение, чтобы **forward** значения как отдельные аргументы. Это разные стороны границы вызова. Словарь для `**` должен иметь подходящие строковые ключи, совпадающие с допустимыми именами параметров вызываемой функции.

```pycon
>>> def describe(document_id, language):
...     return f"{document_id}:{language}"
>>> positionals = ("doc-7",)
>>> keywords = {"language": "en"}
>>> describe(*positionals, **keywords)
'doc-7:en'
```

Здесь `*positionals` передаёт `"doc-7"` как первый позиционный аргумент, `**keywords` передаёт `language="en"`. Типичная ошибка — думать, что `*args` в определении и `*positionals` в вызове оба собирают значения. Ещё одна — передать один и тот же параметр дважды, через позицию и имя.

## 4. Замыкание и время значений по умолчанию

**Замыкание (closure)** появляется, когда внутренняя функция использует имя из охватывающей функции после того, как внешний вызов завершился. Это позволяет вернуть настроенное действие. Здесь достаточно проследить значение настройки; тонкости `nonlocal` и переназначения оставим за рамками.

```pycon
>>> def make_prefixer(prefix):
...     def format_message(message):
...         return f"{prefix}: {message}"
...
...     return format_message
>>> notice = make_prefixer("NOTICE")
>>> notice("document indexed")
'NOTICE: document indexed'
```

`make_prefixer` получает `"NOTICE"`, создаёт внутреннюю функцию и возвращает **её объект**. При последующем `notice(...)` внутренний код ещё видит привязку `prefix` из своего окружения. Если захваченная настройка — изменяемый контейнер, последующие изменения этого контейнера могут отражаться в поведении; вспомните [алиасинг](../01_object_model/theory.md). В практическом задании о фильтре понадобится решить, следует ли сохранять снимок настройки, но решение здесь не дано.

Значение **аргумента по умолчанию (default argument)** вычисляется при выполнении определения функции, один раз для этого созданного объекта функции, а не заново при каждом вызове. С неизменяемой строкой выше это незаметно; с изменяемым списком может возникнуть общее состояние между вызовами. Различайте «аргумент не передали» и «передали конкретный список». Не переносите следующий пример в ученический файл отладки как готовую правку:

```pycon
>>> def collect(value, items=[]):
...     items.append(value)
...     return items
>>> collect("a")
['a']
>>> collect("b")
['a', 'b']
```

Прогноз № 2: если второй вызов здесь заменить на `collect("b", [])`, какой список получится и будет ли изменён список, сохранённый в default? Сначала объясните, какой объект передан явно. Типичная ошибка — ожидать, что запись `items=[]` создаёт пустой список на каждый вызов. Самостоятельное исправление реального симптома оставлено заданию [Debug leaking audit tags](debugging/mutable_defaults/README.md).

## 5. `enumerate` и `zip`: индекс и пара — не проверка длины

`enumerate(iterable, start=0)` даёт пары `(номер, значение)`; при `start=1` счёт начинается с единицы. `zip(a, b)` даёт пары элементов из двух итерируемых объектов. Обе функции возвращают итерируемые результаты; здесь `list(...)` нужен только для видимого вывода.

```pycon
>>> list(enumerate(["en", "fr"], start=1))
[(1, 'en'), (2, 'fr')]
>>> list(zip(["en", "fr", "de"], [2, 1]))
[('en', 2), ('fr', 1)]
```

По умолчанию `zip` останавливается на **кратчайшем** входе; `de` во втором результате отсутствует. Это ловушка, если задача требует обнаруживать лишние или недостающие ответы: красивый список пар ещё не подтверждает равную длину. `zip(..., strict=True)` может сообщить о несовпадении длины при потреблении, но особенности однократного потока и контракта ошибки нужно продумать в самом задании. Готового алгоритма для [Combine provider responses](exercises/combine_responses/README.md) здесь нет.

Прогноз № 3: что изменится в первом результате, если убрать `start=1`? А во втором, если добавить третье число? После прогноза объясните, почему совпавшее число пар ещё не доказывает, что оба исходных потока имели одинаковую длину.

## 6. Самопроверка после своей попытки

<a id="answers"></a>

Ответьте на семь вопросов [README](README.md#self-check) своими словами и на новом сообщении.

<details><summary>1 и 5. Функция как значение</summary>

Да: имя может ссылаться на объект функции. Передача имени без скобок передаёт действие; скобки вызывают его и передают результат. `lambda` подходит для короткого прозрачного выражения; именованная функция лучше для нескольких шагов или делового смысла.

</details>

<details><summary>2 и 7. Маркеры в определении и вызове</summary>

В сигнатуре отдельная `*` делает следующие параметры keyword-only; `*args` собирает дополнительные positional значения в tuple; `**kwargs` — дополнительные keyword значения в dict. В вызове `*values` и `**mapping` распаковывают и передают отдельные аргументы. `/` ограничивает предыдущие параметры позиционной передачей.

</details>

<details><summary>3–4. Default и closure</summary>

Default вычислен при определении функции; изменяемый список может оставаться общим для вызовов без явного аргумента. Замыкание — внутренняя функция с доступом к привязке из внешней области после выхода внешней функции. Если настройка изменяема, важно осознанно решить вопрос снимка и общего объекта.

</details>

<details><summary>6. Индексы и выравнивание</summary>

`enumerate` выдаёт значение вместе со счётчиком, по умолчанию с нуля. `zip` попарно идёт по входам и без `strict=True` прекращает работу при исчерпании кратчайшего; результат не валидирует длины автоматически.

</details>
