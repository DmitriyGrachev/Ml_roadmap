## Контракты

`lower_bound(values: Sequence[int], target: int) -> int` получает отсортированную
по возрастанию последовательность и возвращает индекс первого значения не меньше
`target`, либо `len(values)`. Для равных чисел нужен первый допустимый индекс.
Объясните, почему число сравнений растёт логарифмически; тест считает сравнения
значений на 1024 элементах и не использует секундомер.

`top_k(values: Iterable[int], k: int) -> tuple[int, ...]` возвращает не более `k`
наибольших чисел по убыванию. Повторы сохраняются. При `k=0` и пустом входе ответ
пустой; при `k` больше длины возвращаются все числа. `k<0` — `ValueError` с `k`
в сообщении. Вход может разрешать только один проход. Защитите оценку
`O(n log k)` и состояние ограниченной кучи `O(k)` для `k>0`. Проверка наблюдает
один проход, но не доказывает ограничение общей памяти вашей реализации.

`reachable(graph: Mapping[str, Sequence[str]], start: str, *,
traversal: Literal['bfs', 'dfs']) -> tuple[str, ...]` возвращает вершины,
достижимые из `start`, включая саму начальную вершину. При `bfs` порядок по уровням,
при `dfs` — глубинный preorder; в обоих случаях соседи посещаются в данном порядке.
Цикл не повторяет вершины, несвязанные вершины не входят в ответ. Неизвестный
`start` — `ValueError` с `start` в сообщении. Объясните `O(V+E)` для посещённой
части графа и память на отмеченные вершины и фронтир.

## Запуск и защита

Из корня репозитория или с тем же интерпретатором в PyCharm:

```powershell
uv run python scripts/learn.py test python-interview-patterns
uv run python scripts/learn.py check python-interview-patterns
```

`test` показывает ожидаемые xfail от незавершённых TODO; `check` требует всех
student assertions без xfail/skip. Отдельный unit проверяет измерительные входы.
Здесь нет внешнего smoke, базы или ML evaluation. Своё обоснование отдайте на
содержательную проверку (`REQUIRES_REVIEW`), используя общий
[шаблон защиты](../../../../docs/project-defense.md): покажите новую вариацию
входа, инвариант каждого шага и границу применимости оценки сложности.

## Подсказки по этапам

1. Зафиксируйте значение позиции вставки до каждого сравнения и после него.
2. Разделите порядок результата top-k и количество хранимых кандидатов; повтор
   значения не означает повторную итерацию источника.
3. Перед обходом определите момент, когда вершина становится «увиденной», и
   проверьте порядок на ромбе с циклом.
