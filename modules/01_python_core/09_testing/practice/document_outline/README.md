# Самостоятельная практика: обработчик оглавления и review AI-кандидата

Это ручная практика для будущего A1, без нового ID, автоматического зачёта или
изменения progress. Она продолжает [разбор тестов](../../theory.md) и
[декомпозицию функций](../../../03_functions/README.md). Учитель разобрал подсчёт
слов по абзацам; здесь другая задача: извлечение заголовков. Готовых тестов и
решения этой задачи нет. Файлы `outline_cases.py` и `review.md` изначально пусты.

## Сначала контракт v1

В `starter.py` реализуйте `extract_outline(text: str) -> tuple[str, ...]`.
Вход — строка в памяти; чтение файлов, сеть и Markdown-библиотека не нужны.

- Только строки, начинающиеся **ровно с `# ` в колонке 0**, являются заголовками.
  `## Detail`, ` # Indented` и `#NoSpace` не подходят.
- Удалите эти первые два символа, затем пробелы по краям заголовка.
- Пустые заголовки пропустите. Сохраните внутренние пробелы, порядок и повторы.
- Пустой документ даёт пустой tuple. Вызовы независимы. Вход не изменяется.
- Нестроковый вход отвергается с `ValueError`, называющим `text`.

До кода заполните таблицу «вход → буквальный ожидаемый результат → какое нарушение
ловит тест» в `review.md`. Спроектируйте ordinary, empty, invalid и boundary cases,
включая отсутствие пробела после `#`, похожий подзаголовок и два последовательных
вызова. Не вычисляйте ожидаемый результат функцией, которую проверяете.

Добавьте свои pytest-тесты в `outline_cases.py`. Для первой версии используйте
`from .starter import extract_outline`; файл `__init__.py` позволяет относительный
импорт. Проверьте RED на TODO, затем минимально реализуйте контракт и получите GREEN.
Не добавляйте `xfail`, `exercise_call`, подавление ошибок или тесты только на наличие функции.
Сохраняйте это имя файла: оно не соответствует обычному автопоиску pytest.
Поэтому собственные тесты не расширяют существующий check урока `python-testing`
или общий автопоиск репозитория. Явный путь ниже всё равно запускает функции `test_*`.

Из корня репозитория, с уже подготовленным окружением:

```powershell
uv run --no-sync pytest modules/01_python_core/09_testing/practice/document_outline/outline_cases.py -q
```

До написания тестов команда заканчивается `no tests ran`, **exit code 5**. Это
не PASS. После появления тестов `NotImplementedError` — ожидаемый RED, также
не признак освоения. Не ограничивайтесь одним примером, который кандидат случайно проходит.

## Затем изменение требования v2

После зелёной v1 добавьте keyword-only аргумент `unique: bool = False`.
При `False` поведение v1 сохраняется. При `True` одинаковые после `casefold()`
заголовки объединяются: оставьте первое написание и место первого появления.
`"API"` и `"api"` в этом режиме — один заголовок. Пробелы по краям уже удалены;
внутренние не нормализуются. Нестроковый `text` по-прежнему недопустим; `unique`
принимает только `bool`, иначе `ValueError`, называющий `unique`.

Сначала допишите тесты изменившегося поведения, убедитесь в RED, затем измените
реализацию. Покажите, что старые тесты остаются зелёными. Объясните, на каком этапе
составного преобразования должно работать устранение повторов и почему состояние
этого этапа принадлежит одному вызову.

## Review кандидата

`candidate.py` — намеренно дефектный образец якобы полученного AI-кода для v2.
Его не следует использовать как реализацию. Сначала прочитайте его и запишите
предположения в `review.md`, затем направьте **свои** тесты на кандидата:
временно замените импорт на `from .candidate import extract_outline`.
Используйте ту же команду выше. Красный результат здесь полезен, но сам по себе
не завершает review. Верните импорт к `starter` перед финальной проверкой своей работы.

В отчёте для каждого найденного дефекта нужны конкретное требование, минимальный
контрпример, фактическое поведение, причина и предлагаемая граница функции.
Отделите ошибки результата от удобства сопровождения. Не считайте ответ AI
доказательством корректности: доказательства — воспроизводимые случаи и объяснение.
Никакой код не отправляется внешнему AI-сервису этой практикой.

## Ручной критерий готовности

Собственные непустые тесты охватывают контракт и требование v2; вы можете показать
RED/GREEN, объяснить независимость вызовов, назвать первое неверное предположение
кандидата и обосновать декомпозицию. Проверяющий читает тесты и отчёт вручную.
Успех авторских демонстраций и пустой `review.md` не заменяют эту работу.

Дальше используйте существующие задания
[`python-debug-mutable-defaults`](../../../03_functions/debugging/mutable_defaults/README.md) и
[`python-review-stateful-report`](../../../03_functions/code_review/stateful_report/README.md).
В первом уже есть дефект разделяемого состояния; во втором корректное поведение
закреплено characterization tests, и меняется структура кода. Их файлы и зачёт
остаются отдельными от этой ручной вариации.
