# Collections: выбрать структуру по вопросу к данным

[Вход и задания](README.md) · [Запускаемый пример](example.py)

## 1. Задача и первый прогноз

В потоке метаданных документа языки встречаются повторно. Хотим получить список уникальных языков в понятном порядке и число появлений каждого. До запуска [example.py](example.py) предскажите: сохранится ли исходный порядок `en, fr, de` после `set`? Почему у результата два разных контейнера?

Это урок после [Object Model](../01_object_model/README.md). Его модель привязки имён объясняет, почему изменение списка видно через другое имя и почему неглубокая копия не копирует вложенные объекты. Здесь выбираем контейнер и способ доступа; устройство памяти повторно не разбираем.

## 2. Четыре контейнера — четыре типичных вопроса

Представьте данные как разные способы ответить на вопрос. Список хранит последовательность; кортеж фиксирует позиции записи; множество отвечает, встречалось ли значение; словарь связывает ключ со значением. Это интуиция выбора, а не утверждение, что один контейнер всегда быстрее любого другого.

| Контейнер | Типичный вопрос и доступ | Порядок | Изменение самого контейнера |
| --- | --- | --- | --- |
| Список (list) `[]` | «Какой элемент на позиции 1?» — `items[1]` | Порядок элементов сохраняется; повторы допустимы | Можно добавлять, удалять, заменять |
| Кортеж (tuple) `()` | «Какое поле на позиции 1?» — `row[1]` или распаковка | Порядок фиксирован; повторы допустимы | Нельзя заменить поле самого кортежа; вложенный изменяемый объект остаётся изменяемым |
| Множество (set) `set()` | «Есть ли значение?» — `value in seen` | Порядок обхода не служит контрактом | Можно добавлять/удалять элементы; повторы исчезают |
| Словарь (dict) `{}` | «Какое значение у ключа?» — `counts[key]` | Обход идёт в порядке вставки ключей, не сортировки | Можно менять значения и добавлять ключи |

Списки и кортежи допускают доступ по индексу, начиная с 0. Для множества и словаря такой индекс не описывает нужный вопрос: у словаря доступ идёт по ключу, у множества — проверкой принадлежности. Элементы множества и ключи словаря должны быть хешируемыми; обычный список для этой роли не подходит. `set()` создаёт пустое множество, а `{}` — пустой словарь. Java-аналогии `List`/`Set`/`Map` помогают узнать назначение, но не заменяют проверки конкретных Python-правил порядка и изменяемости.

```pycon
>>> languages = ["en", "fr", "en"]
>>> languages[1]
'fr'
>>> "en" in set(languages)
True
>>> len(set(languages))
2
>>> counts = {"en": 2, "fr": 1}
>>> counts["fr"]
1
```

Здесь `set(languages)` убирает второй `en`; `len` считает элементы. Не выводите из этой демонстрации определённый порядок самого множества.

## 3. Запускаемый пример: от каждой строки к выводу

<a id="example"></a>

В [example.py](example.py) функция `language_summary()` создаёт `languages = ["en", "fr", "en", "de"]`. Затем `set(languages)` оставляет три уникальных значения. `sorted(...)` возвращает **новый список** с алфавитным порядком `de, en, fr`. Поэтому `unique` пригоден и для стабильного обхода, и для вывода.

Следующая строка — словарное включение (dictionary comprehension): `{language: languages.count(language) for language in unique}`. Для каждого языка из уже отсортированного `unique` выражение слева от `for` образует пару ключ → число. `list.count` снова просматривает **весь** исходный список и считает равные элементы: `de → 1`, `en → 2`, `fr → 1`. Так что ключи словаря вставлены в отсортированном порядке именно благодаря обходу `unique`. Сам словарь лишь сохраняет этот порядок вставки; он не сортирует ключи автоматически.

`return unique, counts` возвращает кортеж из двух результатов. В `main()` запись `unique, counts = language_summary()` распаковывает его в два имени. Последний `print` формирует одну строку. Из корня репозитория:

```powershell
uv run --offline --no-sync python modules/01_python_core/02_collections/example.py
```

Тот же запуск в самодостаточной интерактивной проверке (путь считается от корня репозитория):

```pycon
>>> import runpy
>>> runpy.run_path("modules/01_python_core/02_collections/example.py", run_name="__main__") and None
languages=['de', 'en', 'fr']; counts={'de': 1, 'en': 2, 'fr': 1}
```

`runpy.run_path` исполняет существующий файл. Выражение `and None` не добавляет к его выводу представление служебного словаря. Это **полный** вывод файла. Ответ на первый прогноз: порядок множества не обещан; `sorted` задаёт порядок списка, а обход списка задаёт порядок вставки ключей.

У этого учебного приёма есть цена: при `u` уникальных языках `count` просматривает список длины `n` по одному разу для каждого языка, то есть делает примерно `u × n` сравнений. Для четырёх элементов это ясно и достаточно. На больших данных повторное сканирование важно заметить, но здесь не подменяйте пример решением заданий на подсчёт транзакций.

## 4. Срез, распаковка, включение и сортировка

**Срез (slice)** `items[start:stop]` берёт элементы начиная с `start` до, но **не включая**, `stop`. Пропуск начала означает 0, пропуск конца — до конца. Граница за пределами списка просто ограничивается длиной; пустой срез допустим. В отличие от среза, одиночный индекс вне диапазона вызывает ошибку.

```pycon
>>> items = ["a", "b", "c", "d"]
>>> items[1:3]
['b', 'c']
>>> items[3:9]
['d']
>>> items[:2]
['a', 'b']
```

**Распаковка (unpacking)** связывает позиции с именами. Без `*` число значений должно совпасть с числом имён; это полезное ограничение записи, но не заменяет проверку типов и бизнес-правил.

```pycon
>>> row = ("doc-7", "en", 2)
>>> document_id, language, pages = row
>>> document_id, pages
('doc-7', 2)
```

**Включение списка (list comprehension)** сначала перебирает значения после `for`, затем при наличии `if` отбирает их, а выражение перед `for` создаёт выходной элемент. Получается новый список сразу, а не ленивый Java Stream. Выражение должно оставаться читаемым; несколько сложных условий лучше раскрыть обычным циклом.

```pycon
>>> records = [("doc-7", "en"), ("doc-8", "fr"), ("doc-9", "en")]
>>> [document_id for document_id, language in records if language == "en"]
['doc-7', 'doc-9']
```

**Ключ сортировки (sort key)** вычисляет сравниваемое значение из каждого элемента. Кортеж ключей сравнивается слева направо: следующий компонент решает только при равенстве предыдущего. `sorted` создаёт новый список, `list.sort` изменяет существующий список и возвращает `None`. Явный ключ важен, когда порядок должен выражать правило, а не случайный порядок поступления.

```pycon
>>> rows = [("b", 2), ("a", 2), ("c", 1)]
>>> sorted(rows, key=lambda row: (row[1], row[0]))
[('c', 1), ('a', 2), ('b', 2)]
>>> rows
[('b', 2), ('a', 2), ('c', 1)]
```

Здесь `lambda row: ...` — маленькая функция, возвращающая ключ. Деталь передачи функции как значения раскрыта в [Functions](../03_functions/README.md); для этого примера достаточно подставить поля каждой строки: `(2, 'b')`, `(2, 'a')`, `(1, 'c')`. Типичная ошибка — ожидать, что `sorted(rows, ...)` изменит `rows`, либо путать порядок вставки словаря с сортировкой.

Прогноз № 2: если в последнем фрагменте поменять местами два поля ключа на `(row[0], row[1])`, что станет первым элементом результата? Объясните сравнение первых компонентов до запуска. Прогноз № 3: что вернёт `items[3:9]`, если из примера среза удалить последний элемент? Сравните с попыткой `items[3]` после такого удаления.

## 5. Самопроверка после своей попытки

<a id="answers"></a>

Вернитесь к семи вопросам [README](README.md#self-check). Проверьте объяснение на других значениях, а не только на выводе выше.

<details><summary>1–2. Выбор контейнера</summary>

Для повторных проверок принадлежности и устранения повторов подходит `set`, если значения хешируемы и порядок множества не нужен. Список и кортеж сохраняют позиции; кортеж не позволяет заменить свои поля; словарь сопоставляет уникальные ключи значениям и обходит ключи в порядке вставки. «Есть порядок» не означает «сортируется сам».

</details>

<details><summary>3–4. Границы и распаковка</summary>

Срез исключает правую границу и мягко останавливается у конца списка, поэтому из короткого списка может получиться один элемент или `[]`. Распаковка в три имени требует ровно три значения; при другом количестве Python выдаёт `ValueError`. Корректное количество само по себе не подтверждает смысл полей.

</details>

<details><summary>5. Отбор и проекция</summary>

`if` после `for` решает, попадёт ли текущий входной элемент в результат. Выражение перед `for` решает, *что* попадёт. Поэтому включение может одновременно отбирать строки и брать из них одно поле.

</details>

<details><summary>6–7. Порядок словаря и сортировка</summary>

Словарь сохраняет порядок вставки ключей. Если вставить `fr`, затем `en`, обход покажет `fr`, `en`; `sorted` задаёт иной порядок по сравнению с ключом. `sorted(..., key=...)` возвращает новый список и оставляет исходный список как был. `list.sort(...)` меняет его на месте и возвращает `None`.

</details>
