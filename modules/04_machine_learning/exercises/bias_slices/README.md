# Grouped sensor decisions

ID: `ml-bias-slices`.

Difficulty: Medium. Время: 45–60 минут для кода + 30 минут для собственного исследования.
Prerequisites: циклы, dataclass и [confusion matrix / slices](../../05_evaluation/theory.md),
затем [bias and fairness](../../05_evaluation/bias.md). Модель обучать не нужно.

Синтетический конвейер использует датчики в режимах `cold` и `warm`.
`actual=1` — дефект по независимой проверке, `decision=1` — замороженное предупреждение.
Ни данные, ни критерии не предназначены для решений о людях.

## Один TODO: `grouped_slices`

Реализуйте только функцию в `starter.py`. Валидация и `GroupSlice` предоставлены.
Не вызывайте teacher `summarize_rows`: здесь нужно самостоятельно перенести
подсчёт на три параллельных последовательности и другой формат результата.

- `actual`, `decisions`, `memberships` имеют равные длины; пустые допустимы.
  Метки — точные Python `int` 0/1, включая отказ для `bool` и `1.0`.
- `groups` — непустой tuple уникальных непустых после `.strip()` строк;
  исходный текст сохраняется. Каждая membership входит в `groups`.
  Нарушения дают `ValueError`; текст сообщения не контракт.
- Верните tuple `GroupSlice` **в порядке groups**, включая отсутствующие группы.
  `support` — число строк; TP/FP/FN/TN ориентированы относительно `actual`.
- `selection_rate=(TP+FP)/support`; `tpr=TP/(TP+FN)`;
  `fpr=FP/(FP+TN)`; `precision=TP/(TP+FP)`.
  Любой нулевой знаменатель даёт `None`, наблюдаемый нулевой числитель — `0.0`.
  Сохраняйте целые counts и не округляйте rates. Это намеренно другой контракт,
  чем zero-safe метрики в `ml-evaluation-report` и `ml-threshold-policy`.
- Не изменяйте входы, не обучайте модель, не выбирайте порог, не читайте файлы/сеть.
  Одинаковые входы дают одинаковые значения. Не возвращайте общий fairness verdict.

Например, для `actual=(1,0,0)`, `decisions=(0,1,0)`,
`memberships=("cold","cold","cold")`, `groups=("cold","new")`:
у cold `support=3`, `TP=0,FP=1,FN=1,TN=1`, TPR=0, FPR=1/2,
precision=0, selection rate=1/3; у new counts=0 и все rates=`None`.

## Самостоятельный перенос: состав выборки и качество эталона

Создайте собственную маленькую синтетическую таблицу (не teacher/test fixture):
два режима, не менее двух положительных и двух отрицательных случаев в каждом.
До запуска запишите ожидаемые counts, знаменатели и два проверяемых прогноза.

1. Сохраните решения фиксированными и измените долю cold/warm при сохранении
   их внутренних пропорций ошибок. Сравните общий показатель и срезы до/после.
   Повторы шаблона — учебное перевзвешивание, не новые независимые измерения.
2. Отдельным опытом удалите из аудита отрицательные строки одного режима.
   Покажите, какой знаменатель исчез и почему это не улучшение модели.
3. Придумайте проверяемую гипотезу selection, measurement **или** label bias;
   укажите, какие дополнительные первичные записи отличат её от альтернативы.
   Один count-разрыв не определяет причину. Не подгоняйте существующий test.
4. Выберите один критерий сравнения и цену FP/FN **до** расчёта; назовите
   другой критерий, который он не гарантирует. Сохраните определения меток,
   источник синтетики, состав, код, ожидаемые/фактические значения и ограничения
   в собственном отчёте. Готового отчёта или итогового диагноза здесь нет.

## REVIEW — проверка человеком

Ревьюер сверяет cells с исходными строками, порядок/пустые группы и `None`,
пересчитывает один rate вручную и проверяет отсутствие мутаций. В исследовании
нужны собственные прогнозы, различение состава и изменения модели, реальные
знаменатели и объяснение неопределённости с единицей независимости (устройство,
а не зависимые сигналы). Итог отделяет наблюдение от гипотезы и называет
следующую проверку. Автотесты не заполняют этот REVIEW и не дают fairness PASS.
