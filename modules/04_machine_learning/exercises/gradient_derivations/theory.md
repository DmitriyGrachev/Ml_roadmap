# От функции потерь к проверяемому градиенту

## Сначала договоримся о задаче

Одна строка `x_i` содержит `d` признаков; `X` имеет форму `(n,d)`, `y` — `(n,)`,
`w` — `(d,)`, `b` — скаляр. Прогноз регрессии или логит классификации равен
`z = Xw + b`. Здесь нет нескольких выходов на объект: усреднение производится
**только по n объектам**. Формы `(n,1)` и `(n,)` нельзя незаметно смешивать:
NumPy может получить матрицу `(n,n)` вместо вектора ошибок. Проверка форм — часть
математического контракта, а не косметика.

В авторском примере MSE определяется как `L_data = sum_i (z_i-y_i)^2/n`,
без коэффициента `1/2`. BCE определяется как среднее бинарных потерь по объектам.
Полная цель в обоих случаях `J = L_data + lambda/2 * sum_j w_j^2`.
Свободный член `b` не регуляризуется. Поэтому нельзя сравнивать «одинаковую lambda»
с библиотекой, пока не выписаны ее сумма/среднее и коэффициент перед штрафом.
Если считать половину MSE, множитель 2 исчезает и меняется соотношение data/L2.

## Вывод MSE по цепочке

Пусть `r_i=z_i-y_i`. Для одного объекта `d(r_i^2)/dz_i=2r_i`,
`dz_i/dw_j=x_ij`, `dz_i/db=1`. Линейность суммы дает

`dJ/dw_j = (2/n) sum_i x_ij r_i + lambda*w_j`,

`dJ/db = (2/n) sum_i r_i`.

Векторная форма `dw = 2 X.T @ r/n + lambda*w`, `db=2*mean(r)`.
Производная L2 равна `lambda*w`, поскольку производная `w_j^2` равна `2w_j`,
а перед суммой стоит `lambda/2`. Штраф не делится повторно на размер батча.

Ручной пример: `X=[[1],[2]]`, `y=[1,3]`, `w=[1]`, `b=0`.
Прогноз `[1,2]`, остаток `[0,-1]`, MSE `0.5`, `dw=-2`, `db=-1`.
При `lambda=.2` цель становится `.6`, а `dw=-1.8`; `db` остается `-1`.
Шаг gradient descent при `eta=.1` дает `w_new=1.18`, `b_new=.1`.
Подставьте эти значения в цель: уменьшение должно проверяться численно;
слишком большой шаг может увеличить loss даже при правильной производной.

## BCE: почему производная проще исходной записи

Для бинарной метки `y∈{0,1}` вероятность `p=sigmoid(z)`.
Потеря `-y log(p)-(1-y)log(1-p)` имеет производную по `p`
`-y/p+(1-y)/(1-p)`. Умножение на `dp/dz=p(1-p)` сокращает дроби и дает `p-y`.
Следовательно, `dw=X.T@(p-y)/n + lambda*w`, `db=mean(p-y)`.
BCE не имеет множителя 2. Положительный логит при метке 0 должен увеличивать
цель; производная по этому логиту положительна — это простая проверка знака.

Считать вероятность, затем `log(p)` опасно: при `z=1000` вероятность округлится
к единице, а `log(1-p)` даст бесконечность. Используйте эквивалентную запись
`logaddexp(0,z)-y*z`. Для sigmoid безопасно `exp(-logaddexp(0,-z))`:
аргумент exp никогда не положителен. В крайних ошибочных случаях `z=-1000,y=1`
и `z=1000,y=0` loss приблизительно 1000, а `dL/dz` соответственно -1 и +1.
Для правильных крайних случаев loss близок к нулю. Clipping вероятности полезен
для некоторых метрик, но изменяет целевую функцию; не используйте его для
маскировки ошибки в выводе градиента исходной BCE.

## Проверка без доверия к одной реализации

Центральная конечная разность для компоненты theta:
`(J(theta+h e_j)-J(theta-h e_j))/(2h)`, например `h=1e-6` в float64.
Проверяйте и `w`, и `b`, ненулевой L2, несколько признаков, обе функции потерь.
Слишком маленькое h усиливает округление, слишком большое — ошибку аппроксимации.
Проверка loss библиотекой и проверка производной конечными разностями отвечают
на разные вопросы: одинаково ошибочные loss и gradient могут согласоваться
друг с другом. Для MSE авторские тесты дополнительно проверяют стационарность
в решении `sklearn.Ridge(alpha=n*lambda/2)`: sklearn минимизирует сумму квадратов
плюс `alpha*||w||²`. BCE сверяется с `sklearn.metrics.log_loss` на умеренных
логитах без clipping, крайние случаи проверяются отдельно.

## Самостоятельная задача: неодинаковые веса объектов

В starter добавлены веса `a_i>=0`, `S=sum(a_i)>0`.
Взвешенное среднее означает `sum(a_i*loss_i)/S`, а не `/n`.
Это не то же самое, что умножить признаки или метки на веса. Для получения
производных замените каждый вклад объекта на `a_i/S` и оставьте L2 отдельным.
Если все веса умножить на 100, loss и gradient должны остаться прежними.
Нулевой вес исключает data-вклад, но не штраф модели. Взвешивание не исправляет
утечку, неверные метки или неоправданный выбор cost; его смысл нужно объяснить.

Реализуйте `weighted_objective_gradient` для MSE/BCE. Отклоняйте через ValueError
пустую/не двумерную X, несовместимые формы, нечисловые/неконечные значения,
отрицательную/неконечную lambda, неизвестный kind, отрицательные веса или S=0.
Для BCE требуйте бинарные метки. Не изменяйте входные массивы.
Верните `(float, новый вектор dw формы (d,), float db)`.

## Как защищать ответ

Слабый ответ: «NumPy посчитал, loss уменьшается, значит градиент правильный».
Это не объясняет ни масштаб, ни знак, ни то, как сравнивались библиотеки.
Сильный ответ: сначала задает редукцию, выводит производную каждой цепочки,
показывает ручной шаг и finite-difference таблицу для w/b, объясняет alpha в
Ridge и стабилизацию logits, проверяет инвариантность масштаба весов.
Автотесты подтверждают вычисления; объяснение выбора loss и цены ошибок требует
разговора с ревьюером.

Независимый перенос: добавьте наблюдениям разные денежные цены ошибок и решите,
можно ли выразить их одним sample_weight или нужны разные веса для классов.
Выведите новую цель и производные на бумаге, затем создайте собственный fixture
из трех объектов, не совпадающий с демонстрацией. Объясните, что произойдет с
эффективной регуляризацией, если вместо нормировки на сумму весов делить на n.
