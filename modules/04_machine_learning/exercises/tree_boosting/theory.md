# Решающее дерево как перебор и бустинг как исправление ошибок

## Один узел можно проверить полностью

Рассмотрим один числовой признак x. Отсортируйте его **различные** значения
`v1<...<vk`. Кандидаты порога — середины соседних значений `(vj+v(j+1))/2`.
Правило `x<=t` отправляет объект влево, остальные вправо. Перебирать каждое
вещественное число нет смысла: между соседними наблюдениями состав листьев
не меняется. Совпадающие x нельзя разводить по разным листьям одним порогом.
Константный признак не имеет допустимого разбиения.

Классификационный лист предсказывает распределение классов.
Gini `G=1-sum_c p_c²` равен нулю в чистом листе. Выбор узла минимизирует
`(n_left/n)G_left+(n_right/n)G_right`; просто сложить Gini двух листьев неверно,
так как маленький лист получит такой же вес, как большой.
Здесь «weighted» означает вес по количеству строк, а не дополнительные sample weights.
Для labels `[0,0,1,1]` на x `[0,1,2,3]` кандидаты .5,1.5,2.5.
При .5 левый лист чист, правый имеет частоты 1/3 и 2/3, Gini=4/9;
суммарный score `(1/4)*0+(3/4)*(4/9)=1/3`.
При 1.5 оба листа чистые: score=0; при 2.5 снова 1/3.
Выбран 1.5. При равных scores договоримся выбирать меньший порог.
Для x `[0,1,2]`, y `[0,1,0]` оба кандидата дают 1/3, поэтому ответ .5.

## Почему среднее является прогнозом регрессионного листа

Для листа с целью y и константным прогнозом c ошибка
`SSE(c)=sum_i (y_i-c)^2`. Производная `2 sum_i(c-y_i)=0` дает `c=mean(y)`.
Подставляем среднее в каждый дочерний лист, складываем SSE и выбираем минимум.
Эквивалентно минимизировать взвешенную child MSE, потому что общий n одинаков
для всех кандидатов. Нельзя складывать две MSE без весов.

В author demo x `[0,1,3,4]`, y `[0,0,4,4]`.
Пороги .5,2,3.5. Для .5 правый лист `[0,4,4]` имеет среднее 8/3 и
SSE `(8/3)^2+2*(4/3)^2=32/3`. Левый лист дает 0.
Для 2 оба листа постоянны, сумма SSE=0. Для 3.5 симметрично 32/3.
`test_demo.py` проверяет все три кандидата, затем сверяет победивший порог
со sklearn stump. Одна библиотечная accuracy не доказывает правильность перебора.

## Из градиента в остатки

Для функции `L=1/2 sum_i (y_i-F(x_i))²` отрицательный градиент по прогнозу
равен `r_i=y_i-F(x_i)` — остатку. На каждом шаге обучаем небольшой регрессор
h_m **на train остатках**, обновляем `F_m=F_(m-1)+eta*h_m`.
Начальная константа `F_0=mean(y_train)` минимизирует train loss без признаков.
Для MSE без 1/2 отрицательный градиент содержит множитель 2; использование
остатков соответствует другому масштабу шага. Здесь соглашение выбрано явно.
Бустинг не переобучает исходный stump на y на каждом шаге и не использует
validation residuals для fit. Деревья ошибок суммируются, а не голосуют.

Ручной расчет на x `[0,1,2,3]`, y `[0,0,4,4]`, eta=.5:

| Шаг | Прогноз левой/правой группы | Остатки левой/правой группы | Train MSE |
|---|---|---|---|
| 0 | 2 / 2 | -2 / +2 | 4 |
| 1 | 1 / 3 | -1 / +1 | 1 |
| 2 | .5 / 3.5 | -.5 / +.5 | .25 |
| 3 | .25 / 3.75 | -.25 / +.25 | .0625 |

На каждом шаге stump здесь точно описывает две группы остатков.
В более сложной выборке это невозможно: следующий stump может выбрать иной
признак/порог. Снижение train error само по себе не означает улучшения будущих
предсказаний; шумовые остатки тоже можно выучить.

## Выбор шага — отдельная операция

Сохраняйте train/validation MSE **включая шаг 0**. Выберите самый ранний минимум
validation MSE. Нужна копия ансамбля/прогнозов на выбранном шаге; вернуть последний
ансамбль после вычисления правильного selected_step — распространенная ошибка.
Если train y `[0,0,8,8]`, а validation y в обеих группах равно 4, начальная модель
на validation идеальна. Последующие шаги улучшают train и ухудшают validation.
Правильный selected_step равен 0.

Финальный test не участвует ни в выборе числа шагов, ни в eta, глубине или
признаках. После фиксации решения допустимо один раз оценить test; многократный
выбор по нему превращает его в validation. Маленький validation шумный: ранний
минимум тоже имеет неопределенность, которую изучает следующий блок stability.
Author demo намеренно не принимает test labels.

## Что реализовать самостоятельно

`best_gini_split` получает конечный непустой одномерный x и совпадающий вектор
неотрицательных целочисленных классов; возвращает `(threshold, weighted_gini)`.
Не требуйте, чтобы классы начинались с нуля или шли подряд. При константном x
верните `(None,parent_gini)`. Сортируйте уникальные значения и соблюдайте tie rule.

`boost_predict` получает конечные train/validation/query векторы одного признака,
непустые train/validation и соответствующие y. `steps` — неотрицательное целое,
`0<rate<=1`. Разрешен `DecisionTreeRegressor(max_depth=1,random_state=0)`.
Верните dict с `train_mse`, `validation_mse` длины steps+1, `selected_step`
и `query_predictions` именно выбранного ансамбля, формы `(len(query_x),)`.
Query labels отсутствуют. Отклоняйте некорректные данные ValueError.
Авторский пример выводит регрессионные кандидаты и validation snapshots;
learner должен независимо построить классификационный splitter и перенос
выбранного ансамбля на новые query.

Слабый ответ: «sklearn выбрал этот порог, три дерева лучше одного».
Сильный ответ: перечисляет все кандидаты, считает веса листьев, объясняет
SSE/Gini и residual update, показывает случай selected_step=0 и отсутствие
test в подборе. Строгие тесты не проверяют бизнес-цену ошибки — ее обсуждают отдельно.

на бумаге/в своем fixture. Объясните изменение порога и устойчивости SSE;
предложите проверку с другой функцией потерь. Затем придумайте validation,
на котором лучший шаг ровно 1, и продемонстрируйте, что query получает ансамбль
из одного дерева, хотя цикл обучения выполнил три шага.
