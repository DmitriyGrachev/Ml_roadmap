## Геометрия задачи

Матрица обучения `x_train` имеет форму `(n, d)`: `n` строк наблюдений и `d` признаков.
Метки `y_train` имеют форму `(n,)`, матрица запросов `x_query` — `(m, d)`, а ответ —
`(m,)`. Для запроса `q` и строки `x_i` евклидово расстояние равно
`||q - x_i||₂ = sqrt(sum_j (q_j - x_ij)^2)`. Квадрат нормы также можно записать
через скалярное произведение: `q·q + x_i·x_i - 2 q·x_i`. Вариант через разности
проще проверить вручную; при использовании dot-product не допускайте отрицательное
значение под корнем из-за округления.

Расстояние зависит от единиц измерения. В [примере](example.py) одни и те же две
строки меняют порядок близости, если перевести один признак из сантиметров в метры.
В самом `KNNClassifier` масштабирование **не выполняется**. Для реальной оценки
помещайте `StandardScaler` или другой scaler вместе с kNN в pipeline: подбирайте
его параметры только на train каждой складки, затем применяйте к validation/test.
Иначе информация из отложенной выборки попадёт в обучение.

Прямой перебор требует примерно `O(m n d)` арифметики на `m` запросов. Хранение
обучения требует `O(n d)` памяти, а полная матрица расстояний — ещё `O(m n)`;
поштучная обработка запроса может ограничить дополнительную память `O(n)`.
Это подход для маленьких учебных данных, а не обещание быстрого поиска в крупной
базе. Выбор `k` сравнивайте на validation, не на test.

## Задание

Меняйте только [starter.py](starter.py). Реализуйте `KNNClassifier(k)` с методами
`fit(x: NDArray[np.float64], y: NDArray[np.int64]) -> KNNClassifier` и
`predict(x: NDArray[np.float64]) -> NDArray[np.int64]`.

`fit` принимает непустую конечную двумерную матрицу и одномерные неотрицательные
целочисленные метки по одной на строку. Требуется `1 <= k <= n`; данные копируются,
чтобы последующее изменение входа не меняло модель. `predict` до `fit`, неверную
форму, число признаков или неконечный запрос отклоняйте через `ValueError`.
Для каждого запроса выберите `k` ближайших по евклидову расстоянию без весов.
При равном расстоянии сначала идёт строка с меньшим исходным индексом;
при равном числе голосов побеждает меньшая метка. Верните новый `int64` массив.

Подсказки по шагам: (1) выпишите формы и проверки до вычислений; (2) на одном
запросе вручную отсортируйте пару `(distance, row_index)`; (3) отдельно проверьте
равные голоса; (4) проверьте копирование входов и несколько запросов. Пример
показывает только изменение расстояний, не реализацию классификатора.

Из корня репозитория:

```powershell
.venv/Scripts/python.exe -m modules.04_machine_learning.exercises.knn_mechanics.example
.venv/Scripts/python.exe scripts/learn.py test ml-knn-mechanics
.venv/Scripts/python.exe scripts/learn.py check ml-knn-mechanics
```

Unit tests сравнивают случаи без ничьих со sklearn и отдельно проверяют ничьи,
границы и ошибки ввода. Пример — локальный smoke геометрии. Оценка качества на
настоящих данных требует отдельного split/pipeline и сравнения с baseline;
объяснение выбора масштаба и `k` требует review. Пока TODO не завершены, `test`
покажет ожидаемые xfail, а `check` не засчитает упражнение. Готово, когда `check`
проходит без xfail/skip и вы можете объяснить случай равного расстояния.
