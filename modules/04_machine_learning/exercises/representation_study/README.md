## Маленький контракт: обратная карта без fit

Реализуйте `reconstruct_from_components(scores, components, mean)` в `starter.py`.
`scores` формы `(n,k)` — координаты на k осях; `components` формы `(k,p)` —
строки-направления в p признаках; `mean` формы `(p,)` — исходное смещение.
Верните новое `float64` ndarray формы `(n,p)`: линейную комбинацию направлений
для каждой строки с восстановленным смещением. Входы — `float64` ndarray;
пустые оси, несовместимые формы, не двумерные первые два аргумента,
не одномерный mean, NaN/inf должны вызвать `ValueError`.
Входные массивы не меняются, результат не разделяет с ними память.
Обучать sklearn-модель здесь не нужно; компоненты уже переданы. Контракт не
требует проверки ортонормальности и не включает `whiten=True`.

```powershell
uv run pytest modules/04_machine_learning/exercises/representation_study -q
```

До реализации ожидаются `XFAIL` от `exercise_call`; это не выполненное упражнение.
Не меняйте тесты и не подставляйте учительский результат вместо реализации.

## Независимое сенсорное исследование

Создайте свой `experiment.py` рядом. Используйте NumPy и уже установленные sklearn
StandardScaler, PCA, KMeans и IsolationForest; сеть, датасеты и дополнительные
frameworks не нужны. Можно импортировать готовый teacher API через `importlib`,
но генератор и выводы должны быть вашими, не копией трёх probes из урока.

1. До вычислений запишите вопрос и два прогноза. Сгенерируйте независимые train
   и новые readings с фиксированным seed: температура в °C, скорость в rpm,
   два штатных режима и несколько заранее объявленных редких новых режимов.
   Укажите механизм генерации, размеры, единицы и ограничения независимости.
   Редкость по генератору сама по себе не доказывает неисправность.
2. Обучите scaler/PCA/KMeans/IsolationForest только на train. Сохраните параметры,
   train-средние, `components_`, variance ratio, центры и score новых показаний.
   KMeans и лес получают standardized признаки напрямую, PCA исследуется отдельно.
3. Контроль единиц: умножьте **скорость и train, и новых readings** на 1000,
   повторите сравнение raw и standardized расстояний/разбиений. Предскажите,
   где ответ должен сохраниться. Сравнивайте совместную принадлежность пар строк,
   а не номера cluster ID. Не требуйте, чтобы любая смена единиц обязательно
   поменяла raw-разбиение: объясните наблюдаемое на ваших данных.
4. Сравните одну и две компоненты. Своей inverse-map функцией восстановите
   standardized readings, измерьте средний квадрат ошибки по строкам/признакам,
   укажите, что ошибка измеряется в стандартизованных координатах. Проверьте,
   что полный базис даёт почти нулевую ошибку; это не метрика классов.
5. Меняйте один параметр леса: `contamination="auto"` → `0.1`.
   До запуска предскажите смысл изменения порога. Сопоставьте score и число
   тревог на одних новых readings; разберите два случая вручную. Если меток
   неисправности нет, не называйте долю тревог precision или false-positive rate.

Заполните `report.md`: прогнозы **до** запусков, команды/версии/seed, одна таблица
реальных результатов с формами и единицами, подтверждения/опровержения, два
разобранных показания, границы вывода. При наличии уже установленной группы
visualization можно добавить график с подписями осей; таблицы достаточно.
Отдельно объясните: редкий легитимный режим; cluster ≠ class; retained variance
≠ качество классификации. Если хотите оценить неисправности, сначала опишите,
откуда появятся независимые истинные метки, а не назначайте их по score модели.

а вы защищаете новый пример без учительских чисел. Автоматические проверки кода
не завершают исследование и не меняют progress за вас.
