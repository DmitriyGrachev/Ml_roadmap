## Маршрут: теория → скаляр → собственный векторный шаг

Прочитайте [разбор производной, chain rule и шага](theory.md). Сначала письменно
предскажите один скалярный шаг, затем запустите неизменённый [example.py](example.py).
Новый [descent_demo.py](descent_demo.py) показывает несколько learning rates и
численную проверку производной; он импортирует прежние `loss`, `gradient`, `step`.
После этого реализуйте только свой векторный TODO ниже, проверьте его и переходите
к [PyTorch](../../../labs/01_pytorch_foundations/README.md). Теория объясняет
механизм; успешный запуск не заменяет ручную проверку и не ставит progress за вас.

Без записи файлов трассировка выполняется так:

```powershell
uv run --offline --no-sync python -m modules.04_machine_learning.07_training_bridge.descent_demo
```

Для необязательного графика укажите новую папку вывода:

```powershell
uv sync --locked --group visualization
uv run --offline --no-sync python -m modules.04_machine_learning.07_training_bridge.descent_demo --output reports/descent-demo-01
```

Этот второй запуск создаёт `reports/descent-demo-01/descent.png`, CSV с шагами
и численными производными, а также `metadata.json` с параметрами и версиями. Папка
должна быть новой. График и печатная трасса относятся только к синтетическому
примеру, без загрузки данных и без PyTorch.

## Задание: векторный шаг

В [starter.py](starter.py) реализуйте только `gradient_step`:

- weights и gradient: одномерные float64 массивы одинаковой непустой формы;
- все значения конечны; rate конечен и строго положителен;
- нарушенный контракт — ValueError с названием `rate`, `weights`, `gradient` или
  `vector` в сообщении; входы не изменяются;
- результат — новый массив с шагом против градиента, без округления;
- нельзя молча broadcast градиент другой формы.

Это не обучение готовой модели: градиент передаёт вызывающий код. Далее в PyTorch
вы самостоятельно свяжете получение градиента, optimizer и полный lifecycle.

```powershell
uv run python -m modules.04_machine_learning.07_training_bridge.example
uv run python scripts/learn.py test ml-training-bridge
uv run python scripts/learn.py check ml-training-bridge
```

## Подсказки по ступеням

1. До арифметики проверьте ndim/shape/size, затем конечность значений.
2. Выпишите вручную ожидаемый результат для двух весов и разных знаков градиента.
3. Проверьте, что изменение результата после вызова не меняет weights.

## Самопроверка и результат

Почему broadcast полезен в NumPy, но опасен здесь? Чем градиент отличается от
ошибки предсказания? Почему loss на train не измеряет обобщение? Почему seed
не обещает побитовой одинаковости CPU/GPU? Что происходит с накопленным `.grad`
между minibatches в PyTorch? Перед ответами попробуйте
[самостоятельные вариации в теории](theory.md#проверьте-перенос-понимания).

Для `L(w₀, w₁) = (w₀ + 2w₁ - 3)²` выпишите частную производную по `w₁`, удерживая
`w₀` постоянным. Как проверить эту координату центральной конечной разностью?
Если добавить `λ(w₀² + w₁²)`, какой член появится в каждой частной производной
и почему `λ` нельзя выбирать по финальному test? Это вопросы на понимание;
второй `fit` градиентным спуском здесь не нужен.

Готово, когда выбранный `check` завершился успешно без обязательных xfail/skip,
вы можете объяснить направление обновления и собственноручно проверить один шаг.
В progress отметку ставите сами. Следующий шаг — [PyTorch](../../../labs/01_pytorch_foundations/README.md).
Перед модельными опытами прочитайте [общий протокол эксперимента](../../../docs/experiment-protocol.md).
