## Цель и теория

NumPy вычисляет результат по заданным параметрам. Обучение выбирает параметры,
уменьшающие loss на train, и проверяет перенос на validation. Финальный test
не подбирает ни параметры, ни число эпох. Метрика отвечает на вопрос о пользе,
loss — на вопрос, куда двигать параметры; они могут различаться.

Для регрессии MSE — средний квадрат ошибки. Квадрат усиливает влияние больших
ошибок, а единица измерения становится квадратом исходной. Для классификации
cross-entropy штрафует малую вероятность правильного класса. PyTorch
CrossEntropyLoss принимает **logits**, не softmax probabilities; нормализация
встроена численно устойчиво. L2-регуляризация штрафует большие веса; её силу
выбирают на validation, а не на test.

Градиент — вектор локальных наклонов loss по параметрам, той же формы, что веса.
Положительная производная говорит: небольшое увеличение параметра увеличит loss.
Градиентный спуск делает шаг в противоположную сторону; слишком большой learning
rate может увеличить loss или дать NaN. Нулевой градиент не доказывает оптимальность.
Chain rule перемножает локальные производные по цепочке вычислений.

В [примере](example.py) `loss(a)=(2a-3)^2`: производная внешнего квадрата умножается
на внутренний наклон 2. Проверьте её центральной конечной разностью
`(loss(a+epsilon)-loss(a-epsilon))/(2*epsilon)`. Это диагностический приём;
слишком маленькое epsilon усиливает ошибку округления. Autograd в следующей
лабораторной выполняет chain rule по вычислительному графу, не конечные разности.
Геометрию без градиентного обучения можно отдельно проверить в
[ручном kNN](../exercises/knn_mechanics/README.md).

## Задание: векторный шаг

В [starter.py](starter.py) реализуйте только `gradient_step`:

- weights и gradient: одномерные float64 массивы одинаковой непустой формы;
- все значения конечны; rate конечен и строго положителен;
- нарушенный контракт — ValueError с названием `rate`, `weights`, `gradient` или
  `vector` в сообщении; входы не изменяются;
- результат — новый массив с шагом против градиента, без округления;
- нельзя молча broadcast градиент другой формы.

Это не обучение готовой модели: градиент передаёт вызывающий код. Далее в PyTorch
вы самостоятельно свяжете получение градиента, optimizer и полный lifecycle.

```powershell
uv run python -m modules.04_machine_learning.07_training_bridge.example
uv run python scripts/learn.py test ml-training-bridge
uv run python scripts/learn.py check ml-training-bridge
```

## Подсказки по ступеням

1. До арифметики проверьте ndim/shape/size, затем конечность значений.
2. Выпишите вручную ожидаемый результат для двух весов и разных знаков градиента.
3. Проверьте, что изменение результата после вызова не меняет weights.

## Самопроверка и результат

Почему broadcast полезен в NumPy, но опасен здесь? Чем градиент отличается от
ошибки предсказания? Почему loss на train не измеряет обобщение? Почему seed
не обещает побитовой одинаковости CPU/GPU? Что происходит с накопленным `.grad`
между minibatches в PyTorch?

Для `L(w₀, w₁) = (w₀ + 2w₁ - 3)²` выпишите частную производную по `w₁`, удерживая
`w₀` постоянным. Как проверить эту координату центральной конечной разностью?
Если добавить `λ(w₀² + w₁²)`, какой член появится в каждой частной производной
и почему `λ` нельзя выбирать по финальному test? Это вопросы на понимание;
второй `fit` градиентным спуском здесь не нужен.
