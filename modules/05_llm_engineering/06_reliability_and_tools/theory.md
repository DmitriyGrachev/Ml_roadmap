# 06. Сбой, поток и предложение действия

Практический вопрос: модель ответила не полностью или предложила прочитать закрытый справочник. Когда повторять запрос, а когда остановить функцию? Предпосылки — [граница интерфейса](../01_llm_interfaces/theory.md), [проверка output](../03_structured_outputs/theory.md) и [существующий пример разрешённого tool read](example.py).

Интуиция: **timeout** ограничивает ожидание одной операции на transport boundary; **bounded retry** повторяет только классифицированный временный сбой с общим лимитом попыток и времени. Повтор не делает неверный JSON или запрещённое действие правильным. Истёкший timeout не доказывает, что удалённая сторона ничего не сделала. Перед повтором действия с эффектом нужна договорённость об idempotency и подтверждение; teacher walkthrough не выполняет внешних действий.

Маленький пример: `cases.truncated` содержит начальный кусок JSON и normalized reason `length`; `decide_completion` отвергает его до разбора схемы. `cases.refusal` сообщает отказ отдельно. `cases.malformed` доходит до schema failure; `cases.empty` — до проверки непустого технического результата. Не отправляйте пользователю частичный текст как законченный ответ. Если API передаёт **streaming** chunks, приложение собирает их в порядке конкретного протокола, ждёт терминального события, проверяет завершение и только затем валидирует итог. Уже декодированная строковая content delta может разрезать JSON посередине строки, но не содержит половину UTF-8 символа; на уровне транспортных byte chunks граница может попасть внутрь UTF-8 последовательности, поэтому декодирование там должно быть инкрементальным. Формат событий отличается по API. [Самостоятельное stream exercise](../exercises/stream_assembly/README.md) задаёт свой узкий формат, не универсальный streaming standard.

Tool calling — предложение имени операции и аргументов, а не полномочие модели. В прежнем [примере](example.py) приложение выбирает разрешённый `lookup_book` и проверяет `can_read` вне текста модели. В сервисном сценарии защищённый staff guide вообще не попадает в запрос посетителя: `cases.denied` показывает `request=null`, `completion=null`. Если модель попросит `publish_policy` или выдаст `admin=true`, приложение не исполняет текст. Разрешённые операции перечислены в коде, аргументы проверяются, права пользователя подтверждаются приложением до чтения; операция с последствиями потребовала бы отдельного подтверждения и аудита. Локальные проверки доказывают только конкретный application gate.

Повтор запроса на `timeout` — отдельное решение от чтения неполного stream: сначала выясните, окончен ли поток и допускает ли поставщик безопасный retry. При попытках 1–3 с задержками после 1 и 2 суммарное время включает ожидание каждой попытки, задержки и возможные расходы. Бесконечный цикл или сон после последней неудачи нарушает deadline. Вложенные повторы SDK и приложения могут умножить число вызовов. Логи сохраняют ID, версию, этап отказа и минимально нужное usage; source text, access code и секреты туда не копируют.

Кэш ответов добавляет ещё одну гипотезу: тот же normalized request, модель, prompt, право доступа и версия источника должны означать допустимое повторное использование. В `G-01` смена правила после `2026-09` делает старый ответ сомнительным. Учебный [response cache](../exercises/response_cache/README.md) имеет собственный контракт срока жизни и версий; teacher trace его не реализует. Кэш не заменяет повторной авторизации на защищённый текст.

Типичная ошибка — автоматически повторить `refusal` или принять частичную stream-дельту как JSON. Самостоятельная вариация: первая попытка истекла по timeout, вторая вернула `length`, третья недоступна из-за общего deadline. Что показать пользователю и какие события можно безопасно записать без текста источника? Ограничение: нет сети, настоящего провайдера, stream API, side effects и доказательства идемпотентности.

## Источники и практика

- AWS, [Retry with backoff pattern: implementation and issues](https://docs.aws.amazon.com/prescriptive-guidance/latest/cloud-design-patterns/retry-backoff.html), англ.: когда ограничивать повтор и почему учитывать idempotency; остановитесь до облачной конфигурации.
- Hugging Face, [GenerationConfig: length parameters](https://huggingface.co/docs/transformers/v5.17.0/en/main_classes/text_generation#transformers.GenerationConfig), англ.: конкретный смысл ограничения нового вывода, не universal `finish_reason`.
