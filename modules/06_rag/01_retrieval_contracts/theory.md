# 01. Что обещает поиск и откуда взялся ответ

Практический вопрос: посетитель спрашивает «Можно оставить велосипед на ночь?». В [LLM-контракте](../../05_llm_engineering/02_prompt_contracts/theory.md) уже есть публичный `G-01`: **“Overnight storage is not offered. Pickup by 19:00.”** Как приложение получит именно действующую, доступную версию справочника и сможет показать основание ответа? Запустите из корня `python -m modules.06_rag.walkthrough --output <новый-каталог>`; `trace.json` — учебная трасса, не ответ модели.

Интуиция: **retrieval-augmented generation (RAG)** сначала ищет проверяемые фрагменты, затем передаёт их как данные для ответа. Похоже на сервис, который возвращает запись вместе с её ключом и версией. Но высокий search score говорит о похожих словах, а не о правдивости записи или её праве отвечать на вопрос. Предскажите: должен ли посетитель увидеть служебную заметку, если она лучше всех совпала со словом `access`?

Разобранный маршрут одного запроса; последующие уроки показывают каждую операцию подробнее:

| Этап | Вход → выход и задача | Возможный сбой → различающая проверка |
| --- | --- | --- |
| Документы | публичный `G-01`, другие сервисные страницы, отдельно служебная заметка → snapshot; задать владельца и доступ | старая/закрытая страница → сверить реестр источников, права и дату |
| Извлечение/очистка | исходный текст → нормализованные абзацы; убрать технический шум, сохранив отрицание | потеряно `not` или исключение → сравнить raw и extracted text |
| ID, версия, metadata | абзац → `source_id`, `revision`, `access`, digest; проследить происхождение | тот же ID у нового текста → проверить revision и digest |
| Chunking | абзацы → `G-01@2026-09:p1`, `:p2`; выбрать единицу поиска | правило разрезано от условия → посмотреть границы и исходник |
| Индекс | разрешённые chunks → словарь TF-IDF и матрица; ускорить поиск | индекс хранит старую ревизию → сравнить индексный snapshot с текущим |
| Запрос | русский вопрос → явно записанный учебный английский lookup `overnight storage`; сформировать запрос | перефразирование не попало в словарь → проверить query vector и ручную разметку |
| Retrieval | query vector + разрешённый индекс → score/rank/top-k; найти кандидатов | нужный chunk ниже cutoff → проверить полный разрешённый список до cutoff |
| Fusion/rerank, если нужны | несколько разрешённых списков/shortlist → новый порядок; улучшить покрытие | отсутствующий кандидат не появится → сверить входные списки |
| Контекст | кандидаты + текущие права/версии + budget → passages; дать модели только допустимое | старая/закрытая запись попала в context → повторно проверить metadata и digest |
| Иллюстративный ответ | вопрос + context → заранее подготовленная фраза; показать вид результата | правдоподобное утверждение без основания → сравнить каждое утверждение с текстом |
| Citation/answer check | фраза + IDs/цитаты → решение показать/воздержаться | существующий ID, но цитата не поддерживает вывод → раздельная проверка ссылки и смысла |

В `found` локальный TF-IDF ставит `G-01@2026-09:p1` первым с cosine `0.525060` (значение вычислено кодом для этого snapshot). Контекст сохраняет `source_id=G-01`, `revision=2026-09`, digest и текст; подготовленный ответ: «Нет. Ночное хранение не предлагается; заберите велосипед до 19:00». Это узкий пример с известным автору фактом. Не делайте из числа `0.525060` вероятность правильного ответа.

Точный контракт: идентификатор chunk зависит от `source_id + revision + номер абзаца`; digest дополнительно привязан к нормализации и политике разбиения. У пользователя есть роль, которую задаёт **trusted application/authentication logic**; текст вопроса и найденной страницы роли не добавляет. В учебном корпусе служебная `G-STAFF` показана лишь в `teacher_corpus_only` для преподавателя. Пользовательская часть трассы её текст, ID и даже кандидатный ранг не сериализует: ACL применён до построения матрицы, top-k и контекста. Реальная аутентификация здесь не реализована. Даже разрешённая страница остаётся **untrusted data**: строка `Ignore previous instructions...` не становится командой приложению. Тест подтверждает только эту локальную политику, не безопасность произвольной модели.

Типичная ошибка — передать модели глобальный top-k, а потом удалить закрытые фрагменты: закрытый лучший hit вытеснит доступный, а промежуточный лог уже может утечь. Самостоятельная вариация: разрешённая страница стала закрытой после поиска, но до сборки контекста. Укажите две точки проверки доступа и ожидаемую форму ответа, не меняя учебный код. Ограничение: этот walkthrough использует локальный синтетический корпус и не вызывает модель, tool или сеть; ответы подготовлены автором.

Практика: [контракт авторизованного vector search](../03_lexical_dense_retrieval/exercises/vector_search/README.md), ID `rag-vector-search`, требует собственного алгоритма и иных данных. Предскажите, какие passages дойдут до контекста при ограничении доступа. Не используйте teacher trace как готовый ответ на TODO.

## Источники

- Lewis et al., [Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks](https://arxiv.org/abs/2005.11401), англ.: постановка retrieval + generation; здесь остановитесь на общей схеме, не переносите вероятностную модель статьи на TF-IDF demo.
- scikit-learn 1.9, [TfidfVectorizer](https://scikit-learn.org/1.9/modules/generated/sklearn.feature_extraction.text.TfidfVectorizer.html), англ.: параметры `lowercase`, `norm`, `smooth_idf`; в уроке 03 сравните с реальной трассой. Ссылки на API сверены для локальной версии 1.9.1; это справка, а не подтверждение качества ответов.
