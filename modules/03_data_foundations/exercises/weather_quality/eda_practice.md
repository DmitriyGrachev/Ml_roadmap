# Погодные наблюдения: качество данных → EDA → четыре графика

Этот дополнительный практикум продолжает [урок о качестве данных и разведочном
анализе (EDA)](../../03_data_quality/eda.md) на другом, вымышленном наборе данных.
Сначала прочитайте [описание файла](fixtures/README.md), затем используйте
[eda_weather.csv](fixtures/eda_weather.csv). Файл уже находится в репозитории;
скачивать данные не нужно. После уроков Pandas, качества данных и EDA с
Matplotlib работа займёт примерно 60–90 минут.

В [упражнении `summarize_weather`](README.md) задан строгий контракт отчёта о
качестве и сводки по станциям. Свою готовую функцию можно использовать для
дополнительной сверки, но здесь другой вопрос: какие наблюдения подходят для
каждого графика? Не меняйте исходный CSV и не считайте, что одна очищенная
таблица обязательно годится для всех графиков.

## Сначала исследуйте качество данных

1. Загрузите CSV с помощью Pandas из корня репозитория. Перед преобразованием
   и отбором сохраните исходные значения и порядок строк в отдельной таблице.
   Проверьте названия столбцов, число строк, типы данных (dtypes), пропуски,
   даты, преобразование чисел, названия станций и повторяющиеся пары
   `station`–`day`. Если у двух строк один ключ, но разные измерения,
   объясните, как будете с ними поступать: это не дополнительный день.
2. Составьте краткий реестр проблем (issue register) своими словами: какое
   правило проверено, какие позиции строк затронуты, почему это важно и какое
   действие вы предлагаете. Запишите исходное число строк и число строк для
   каждого графика, чтобы можно было проследить исключения. Различайте
   отсутствующее измерение, некорректное значение и повторяющийся ключ.
   Объясните выбор между повторяющимися записями.
3. Сначала исследуйте необычные, но допустимые измерения. Если исключаете или
   отмечаете такое значение, обоснуйте решение и проверьте, меняется ли ваш
   вывод. Необычная точка на рисунке сама по себе не ошибка. Сохраняйте
   единицы измерения: температура в °C, осадки в мм.

Для разных вопросов нужны разные поля. Строка с пригодной температурой и
пропущенными осадками может участвовать в распределении температуры. Для
диаграммы рассеяния (scatter plot) нужны оба допустимых числовых измерения в
одной сохранённой строке. Временной график требует корректной даты; прежде
чем соединять точки, отсортируйте их по дате. Последовательно применяйте
описанное вами правило для повторяющихся ключей и записывайте размер выборки
(sample count) для каждого графика отдельно. Не превращайте пропущенный день
или недостаток наблюдений по одной станции в нулевое измерение.

## Постройте и объясните четыре графика

Используйте Matplotlib. На каждом графике нужны читаемые подписи, единицы,
заголовок с вопросом и число использованных наблюдений. Рядом с каждым
графиком ответьте на три вопроса: **Для чего он построен? Что именно вы
увидели? Чего он не доказывает?** Опишите собственный результат: готовые
наблюдения для копирования здесь не приведены.

1. **Распределение (distribution).** Покажите допустимые значения
   `temperature_c` на гистограмме (histogram). Выберите ширину или число
   интервалов и объясните, как выбор влияет на вид рисунка. Спросите, где
   сосредоточены наблюдения и требует ли какое-либо значение проверки.
   Гистограмма не показывает причину температуры и не подтверждает точность
   редкого измерения.
2. **Связь пары измерений (pair relation).** Нанесите `temperature_c` и
   `rainfall_mm` на диаграмму рассеяния только для строк, где оба значения
   доступны и допустимы. Спросите, совпадают ли в этой небольшой выборке
   более высокие температуры с большим или меньшим количеством осадков.
   Отметьте наложения, пробелы или необычную пару, если они есть. Видимая
   связь не доказывает, что одно измерение вызывает другое.
3. **Сравнение групп (group comparison).** Сравните сводный показатель
   температуры по группам `station` столбчатой диаграммой или другим простым
   способом. Покажите число наблюдений в каждой группе. Назовите выбранный
   показатель и причину выбора; отдельно рассмотрите разброс, если среднее
   его скрывает. Неравные размеры групп и повторные наблюдения ограничивают
   выводы о различиях между станциями.
4. **Временной ряд (time series).** Постройте сводный показатель температуры
   по дням, отсортированным по разобранному полю `day`. Объясните, как в
   показатель за день входят наблюдения разных станций. Отсутствующие даты
   отмечайте как пропуски, не выдумывая измерения. Спросите, что менялось
   на протяжении показанных дней. Короткий ряд не доказывает долгосрочный
   тренд или его причину.

Можно выбрать другой обоснованный показатель или показать неопределённость
на графике; объясните свой выбор. Делайте графики отдельно, чтобы сравнение
на каждом оставалось понятным.

## Запуск и сохранение работы

Из корня репозитория один раз установите дополнительное окружение для графиков:

```powershell
uv sync --group visualization
```

Напишите собственный анализ в `reports/weather_eda.py` или локальном
notebook внутри `reports/`. Скрипт запускается без повторной синхронизации:

```powershell
uv run --no-sync python reports/weather_eda.py
```

Сохраните свой код, графики, реестр проблем, размеры выборок и краткие
интерпретации в игнорируемой Git папке `reports/`. Готового скрипта и
заполненного отчёта в репозитории нет. Не заменяйте исходный CSV
отредактированными строками.

## Список для ручной проверки

- Исходный файл не изменён; преобразование дат и чисел, а также решения о
  повторяющихся ключах можно воспроизвести по сохранённой работе.
- Для каждого графика указаны правило отбора строк и размер выборки.
  Пропущенные и некорректные значения обработаны в соответствии с вопросом
  графика; необычные значения не удалены без разбора.
- Четыре графика показывают распределение, пару измерений, сравнение станций
  и изменение по времени. Оси и единицы измерения подписаны честно и ясно.
- У каждого графика есть вопрос, конкретное наблюдение по полученному
  рисунку и граница вывода: чего рисунок не доказывает.

Сохранённый код и графики должен посмотреть человек. Существующий
автоматический check `data-weather-quality` этот практикум не оценивает.
