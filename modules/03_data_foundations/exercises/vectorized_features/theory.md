# Маскированные редукции и геометрия похожести

## Prerequisites

Нужны NumPy indexing, булевы массивы, `axis`, формы `(n, d)`, `keepdims`,
скалярное произведение и популяционная дисперсия. Сначала выпишите формы
промежуточных величин, затем проверяйте численное значение.

## Вычисление по наблюдаемым ячейкам

Пусть `M[i,j]` — маска, а `X[i,j]` — значение. Столбцовый счётчик
`c[j] = sum_i M[i,j]`. Среднее `mu[j] = sum_observed X[i,j] / c[j]`;
дисперсия `v[j] = sum_observed (X[i,j]-mu[j])² / c[j]`. Это `ddof=0`:
мы описываем имеющуюся матрицу, а не оцениваем несмещённую дисперсию популяции.
Пустые столбцы обрабатываются отдельно, их среднее ноль. Нулевая дисперсия
заменяется scale один, поэтому константные наблюдения стандартизуются в ноль.

Рабочий вход:

| Строка | Значения | Маска |
|---|---|---|
| 0 | `[2, 8, NaN]` | `[True, True, False]` |
| 1 | `[6, inf, -99]` | `[True, False, False]` |

Счётчики `[2, 1, 0]`, средние `[4, 8, 0]`, scale `[2, 1, 1]`.
Выход `[[-1, 0, 0], [1, 0, 0]]`. Значение `-99` не должно попасть в сумму,
хотя конечно; `inf` не должно испортить вторую колонку. Умножение на маску
не решает проблему: `NaN * 0` и `inf * 0` остаются NaN. Сначала исключайте
ненаблюдаемые значения безопасной операцией выбора, затем выполняйте редукции.
Не вычисляйте NaN-центрирование и только потом не пытайтесь обнулить его умножением.

При `X.shape == (n, d)` вектор средних имеет `(d,)`: broadcasting повторяет
его для каждой строки. `axis=0` убирает ось строк; `axis=1` даёт среднее каждой
строки и решает другую задачу. Деление на `maximum(count, 1)` безопасно для
пустых столбцов, если числитель там уже ноль. Не путайте это с политикой для
константных столбцов: у них счётчик положительный, но дисперсия нулевая.

## Views, copies и временная память

`base[:, ::2]` часто является view с шагом по памяти; присваивание внутрь такого
массива меняет `base`. Операция `x -= mean` нарушает контракт отсутствия мутации.
`reshape` иногда возвращает view, иногда создаёт копию: это зависит от strides.
Проверяйте владение через `np.shares_memory`, а не предполагайте, что любое новое
имя создаёт новый массив. Маска также принадлежит вызывающему коду.

`np.where`, центрирование и возведение в квадрат могут создать несколько
временных матриц `(n, d)`. Каждая `float64` ячейка требует 8 байт. Векторизация
устраняет Python-цикл, но сама по себе не уменьшает объём памяти. Для крупного
потока среднее и дисперсию можно собирать стабильными частичными статистиками;
это расширение потребует отдельной проверки точности и не входит в интерфейс.
Вычитание больших близких чисел и переполнение квадратов — причины проверять
численный диапазон реальных данных, даже если все входы формально конечны.

## Cosine и порядок top-k

`cos(q, x) = (q·x)/(||q||₂ ||x||₂)`. Здесь направление важнее длины. Например,
для запроса `[1, 0]` кандидаты `[2, 0]`, `[0, 3]`, `[0, 0]` дают `[1, 0, 0]`.
Для нулевого запроса все три score равны нулю. При `k=2` оба запроса выбирают
индексы `[0, 1]`: равные score разрешаются исходным индексом.
У кандидата `[-2, 0]` score `-1`; нулевой вектор с политикой score ноль окажется
выше него. Это явное продуктовое решение, а не следствие неопределённого деления.

Нормы запросов формы `(m,)` перед делением требуют оси `(m, 1)`, нормы кандидатов
— `(1, n)`. Полное произведение имеет `(m, n)`. Нельзя делить с надеждой на
случайное совпадение `m == n`; прямоугольный тест обнаруживает ошибку осей.
Сортировка должна разрешать ничьи во **всём** списке кандидатов. `argpartition`
без последующей обработки равенств на границе может исключить меньший индекс.

Арифметика плотного поиска имеет стоимость порядка `O(m n d)`, score-матрица
занимает `8mn` байт. При 10000 запросах и 100000 кандидатах это 8 миллиардов байт
только для score, плюс индексы сортировки и временные массивы. Обрабатывайте запросы
батчами; если батчить также кандидатов, объединяйте текущий top-k с новым блоком
с тем же правилом ничьих. Это сохраняет результат и ограничивает память,
но не превращает полный перебор в приближённый индекс.

## Типичные ошибки и проверка переноса

- Маска заменяется `isfinite(values)`: теряется смысл исключённого конечного значения.
- Пустой столбец получает NaN или scale ноль; downstream-модель получает испорченные признаки.
- `ddof=1` меняет проверяемую статистику и не определён при одном наблюдении.
- Нормализация выполняется по столбцам: близость зависит от чужих кандидатов.
- При ничьих возвращаются случайные индексы; batch size начинает менять ответ.

Перед переносом на эмбеддинги документов проверьте: что означает нулевой вектор,
какие значения действительно наблюдаемы, являются ли масштабы train-only
статистикой, помещаются ли временные массивы в память. Если стандартные признаки
используются для обучения, оценки `mean/scale` следует получать только на train;
здесь функция демонстрирует арифметику одной матрицы, а не готовый preprocessing
pipeline. Самостоятельно выведите ответ для маски из одного `True`, измените
порядок одинаковых кандидатов и объясните новый результат без запуска кода.
