Вы уже умеете выбирать столбцы и строить маски из урока Pandas. Здесь результат —
не «очищенная» таблица, а проверяемый отчёт о том, какие правила нарушены.
Отчёт нужен до решения, исправлять ли строку, запрашивать ли источник или

## 1. Сначала прогноз, потом отчёт

В пачке документов одна строка означает **один поступивший экземпляр записи**,
а `document_id` претендует на роль идентификатора документа. До запуска
предскажите: сколько *строк после первого появления* `D-203` и сколько значений
`language` отсутствует? Считает ли код два появления `D-203` или только второе?

| Позиция | `document_id` | `language` | Повтор ID после первого? | Язык отсутствует? |
| ---: | --- | --- | --- | --- |
| 0 | `D-201` | `en` | нет | нет |
| 1 | `D-202` | `None` | нет | да |
| 2 | `D-203` | `ro` | нет | нет |
| 3 | `D-203` | `ro` | да | нет |

Это точные входные данные [`example.py`](example.py). Каждый `>>>` ниже — ввод
в Python, следующие строки — вывод:

```pycon
>>> import pandas as pd
>>> documents = pd.DataFrame(
...     {"document_id": ["D-201", "D-202", "D-203", "D-203"], "language": ["en", None, "ro", "ro"]}
... )
>>> documents["document_id"].duplicated().tolist()
[False, False, False, True]
>>> documents["language"].isna().tolist()
[False, True, False, False]
>>> report = {
...     "duplicate_document_ids": int(documents["document_id"].duplicated().sum()),
...     "missing_language": int(documents["language"].isna().sum()),
... }
>>> report
{'duplicate_document_ids': 1, 'missing_language': 1}
```

Маска повторов смотрит на ID по порядку: позиции 0–2 ещё не повторяют ранее
виденный ID; позиция 3 повторяет позицию 2. Маска пропусков отмечает только
`None` на позиции 1. Сумма `True` в каждой маске равна 1. Код ничего не удалил
и не заполнил. Две строки с `D-203` здесь полностью совпадают, но отчёт
считает **повтор ID**, а не доказательство двух одинаковых файлов.

Самостоятельная вариация: поменяйте только язык последней строки на `fr`.
Предскажите обе маски и отчёт до запуска. Что теперь можно сказать о записях
с одним ID, чего нельзя сказать о содержимом файлов?

## 2. Единица строки, схема и три вида повторения

Интуиция: у таблицы есть «строки-экземпляры», а у правила — вопрос, считать ли
одинаковыми экземпляры целиком или по выбранному признаку. Как у приёмного
журнала, номер и содержимое записи отвечают на разные вопросы. Граница
аналогии: `DataFrame` не знает, является ли ID уникальным и какая запись верна.
Это договорённость с источником данных.

**Схема (schema)** — ожидаемые имена столбцов, типы и правила допустимых
значений. **Единица строки (row unit)** — что представляет строка: документ,
платёж или наблюдение станции за день. **Ключ (key)** — поле или набор полей,
по которому ожидается уникальность этой единицы. Повтор ID может означать
повтор отправки, новую версию или ошибку присвоения; маска не объясняет причину.

**Дубликат всей строки (duplicate row)**: значения во всех проверяемых столбцах
совпали. **Повтор ключа (duplicate key)**: совпали лишь ключевые поля.
**Конфликтующие записи (conflicting records)**: ключ совпал, а другое важное
поле различается. Последний вывод требует сравнения полей и контекста;
`duplicated()` по ключу недостаточно. Индекс Pandas не становится бизнес-ключом
только потому, что нарисован слева от таблицы.

```pycon
>>> import pandas as pd
>>> rows = pd.DataFrame({"id": ["A", "A", "A"], "status": ["new", "new", "closed"]})
>>> rows.duplicated().tolist()
[False, True, False]
>>> rows.duplicated(subset=["id"]).tolist()
[False, True, True]
```

На позиции 1 совпадает вся строка с позицией 0. На позиции 2 совпал ключ `A`,
но `status` другой: это возможный конфликт, который разрешают по правилам
источника. `keep='first'` по умолчанию оставляет первую встречу без отметки;
`keep=False` отметит **все** строки группы. Типичная ошибка — назвать
`rows.duplicated()` числом повторных ID: здесь это 1 вместо 2.

Самостоятельно: добавьте строку `("B", "new")`. Какие две маски получатся?
Затем поменяйте только её `status`; объясните, почему совпадение не возникло.

## 3. Пропуск, пустой текст, ошибка разбора и бесконечность

Прогноз: сколько значений `isna()` найдёт в `[None, "", "  ", "bad", "inf"]`?
Какие из них станут пропусками *после* числового разбора? Сначала запишите ответ.

**Отсутствующее значение (missing value, NA)** Pandas распознаёт через `isna()`:
например, `None`, `NaN`, `pd.NA`, `NaT` в подходящих типах. **Пустой текст (blank)**
`""` и строка из пробелов — значения, а не автоматически NA. Если контракт
считает их отсутствующими, нужна отдельная проверка с учётом типа и пробелов.
**Неразбираемое значение (unparseable)** — текст, который нельзя преобразовать
по формату. **Неконечное число (non-finite)** — `inf`, `-inf` или `NaN`;
`inf` может быть успешно разобран, но не годится для конечного измерения.

```pycon
>>> import pandas as pd
>>> import numpy as np
>>> raw = pd.Series([None, "", "  ", "bad", "inf", "4"], dtype=object)
>>> raw.isna().tolist()
[True, False, False, False, False, False]
>>> parsed = pd.to_numeric(raw, errors="coerce")
>>> parsed.isna().tolist()
[True, True, True, True, False, False]
>>> np.isfinite(parsed.to_numpy()).tolist()
[False, False, False, False, False, True]
```

До разбора отсутствует только `None`. После разбора четыре позиции имеют `NaN`:
исходный пропуск и три строки, не ставшие числом. `"inf"` превратилось в
бесконечность, поэтому `parsed.isna()` его не заметил, а `isfinite()` отверг.
Типичная ошибка — считать все новые `NaN` «чистыми пропусками»: три из них
говорят о неудачном преобразовании. Храните связь с исходными значениями.

Самостоятельно замените `"bad"` на `"5"` и `"inf"` на `"-inf"`;
предскажите три маски. Решите, какой тест изменился из-за первого значения.

## 4. Политика счёта: проблемы и строки

Два отчёта могут быть верны, хотя суммы различаются. **По проблемам
(per-issue)** каждая маска имеет своё поле, одна строка может попасть сразу
в несколько полей. **По строкам (per-row)** общая маска объединяет условия:
строка с двумя дефектами считается один раз. Прогноз: может ли сумма полей
per-issue быть больше числа строк входа? Проверьте на маленькой пачке:

```pycon
>>> import pandas as pd
>>> batch = pd.DataFrame({"code": [None, "A", "A"], "pages": ["bad", "3", "bad"]})
>>> missing_code = batch["code"].isna()
>>> repeated_code = batch["code"].notna() & batch["code"].duplicated()
>>> bad_pages = pd.to_numeric(batch["pages"], errors="coerce").isna()
>>> [mask.tolist() for mask in (missing_code, repeated_code, bad_pages)]
[[True, False, False], [False, False, True], [True, False, True]]
>>> [int(mask.sum()) for mask in (missing_code, repeated_code, bad_pages)]
[1, 1, 2]
>>> int((missing_code | repeated_code | bad_pages).sum())
2
```

У строки 0 нет кода и неразбираемые страницы; у строки 2 повторился код и снова
неразбираемые страницы. Сумма полей `1 + 1 + 2 = 4`, но проблемных строк 2.
Заголовок и контракт отчёта должны говорить, какую политику использует поле.
У реальных ключей отдельно решают, участвует ли отсутствующий ключ в повторах
и в каком порядке проверяются допустимость строки и повтор ключа.

Типичная ошибка — сложить поля независимого отчёта и назвать результат числом
отброшенных строк. Самостоятельно замените `pages` строки 2 на `"8"`:
предскажите три отдельных счёта и счёт объединения, затем проверьте.

## 5. Даты: разбор не равен проверке контракта

Перед разбором даты укажите допустимый формат, календарность и, если это
момент времени, правило часового пояса. `errors="coerce"` превращает
неудачный разбор в `NaT`, не делает исходную строку корректной.
`errors="raise"` останавливает преобразование на ошибке; выбор зависит от
того, собираете ли вы пакетный отчёт или отклоняете вход сразу.

```pycon
>>> import pandas as pd
>>> dates = pd.Series(["2024-01-02", "2024-02-30"])
>>> parsed = pd.to_datetime(dates, format="%Y-%m-%d", errors="coerce")
>>> parsed.isna().tolist()
[False, True]
>>> dates.tolist()
['2024-01-02', '2024-02-30']
```

Второй текст имеет рисунок `YYYY-MM-DD`, но 30 февраля не существует.
Исходное значение осталось в `dates`; маска сообщает о неудаче. Принимать ли
другой формат или дату без часового пояса — отдельное решение контракта.
Самостоятельно замените вторую дату на `"2024-02-29"` и предскажите маску.

## 6. Отчёт до изменения и происхождение данных

Для воспроизводимости храните **происхождение (provenance)**: какой источник,
версия или дата выгрузки дали пачку; какие правила применялись; сколько строк
было на входе; какие позиции или исходные ID вызвали каждый счёт. Рядом с
преобразованным столбцом сохраняйте исходные значения либо возможность
вернуться к ним. Тогда `errors="coerce"` остаётся проверяемым решением,
а не невидимой «чисткой». Простое `dropna()` может удалить строку из-за
нерелевантного столбца и скрыть причину. Полностью пустая строка тоже требует
проверки смысла источника, а не автоматического удаления.

Когда функция обещает не менять переданный `DataFrame`, можно читать вход
и строить новые объекты; для явной рабочей версии используйте `frame.copy()`.
В Pandas 3 действует **Copy-on-Write**: изменение объекта, полученного
выборкой, не должно побочно записывать в другой объект, с которым он разделяет
данные. Однако `alias = frame` — второе имя *того же* объекта, а цепочка
`frame["x"][mask] = value` не является надёжным способом обновить `frame`.
Для намеренной записи указывайте цель сразу через `.loc`. Подробнее в
[предыдущем уроке о Pandas](../02_pandas_core/theory.md#10-изменение-данных-pandas-3-и-numpy).

```pycon
>>> import pandas as pd
>>> source = pd.DataFrame({"pages": ["3", "bad"]})
>>> working = source.copy()
>>> working["pages"] = pd.to_numeric(working["pages"], errors="coerce")
>>> source["pages"].tolist()
['3', 'bad']
>>> working["pages"].isna().tolist()
[False, True]
```

Это пример границы между источником и рабочей таблицей, а не совет заменять
ошибки на `NaN` без отчёта. `copy()` копирует структуру Pandas, но не является
универсальной глубокой копией вложенных Python-объектов в ячейках.

## 7. Необычное значение — повод проверить правило

Температура `-12 °C` выглядит необычно в одном городе, но может быть нормальной
в другом; дождь `-1 мм` противоречит определению количества осадков.
Различайте **подозрение** и **доказанное нарушение контракта**. Диапазон,
единицы измерения, место и сезон определяют границу. Выброс (outlier) сам
по себе не разрешает удалить строку; её можно отметить для проверки и
сохранить исходное значение. То же относится к полностью пустым строкам.

Самостоятельно: если столбец — температура в °C, допустимо ли `-12` по
известному контракту? Если это осадки в мм, что изменится? Не подменяйте
конкретное правило общей командой удаления.

Ответьте до раскрытия подсказок, затем объясните новый маленький вход:

1. Почему две строки с `D-203` дают счёт 1, а не 2?
2. Когда повтор ключа не является повтором всей строки?
3. Какие из `None`, `""`, `"  "`, `"bad"`, `"inf"` обнаружит `isna()` до разбора?
4. Почему `errors="coerce"` требует сверки с исходными значениями?
5. Как четыре проблемы могут относиться лишь к двум строкам?
6. Что записать, чтобы через месяц повторить отчёт?
7. Почему необычную температуру нельзя автоматически удалить?

1. Первая встреча по умолчанию не отмечена; повторная отмечена.

3. Здесь только `None`; пустой текст и бесконечность не равны NA.
4. Новые `NaN`/`NaT` могут скрывать ошибки разбора; нужны причины и позиции.
5. Строка может одновременно нарушать несколько независимых правил.
6. Источник/версию, входные строки или ID, правила и счёты.
