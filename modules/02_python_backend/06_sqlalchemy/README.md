# 06 — SQLAlchemy 2.x models and sessions

## Goal

Persist typed domain records with SQLAlchemy 2.x while treating a session as a bounded unit of work.

## Java mental model

| Spring | Python and FastAPI |
| --- | --- |
| JPA entity fields map a record. | `Mapped[...]` and `mapped_column` map an ORM model. |
| `EntityManager` manages persistence context. | `Session` manages a unit of work. |

**Non-equivalence:** SQLAlchemy is explicit about statements and session lifetime; it is not JPA with renamed annotations.

## Python model

Use `select()` and typed mappings. Commit a successful unit of work, roll back failures, and close every session through a context manager or request dependency.

Treat ORM metadata and database migrations as different tools. `Base.metadata.create_all()` is handy
for an isolated exercise or test database, but it does not version production schema changes.

The following Alembic commands are conceptual production examples, not runnable repository setup:
this roadmap intentionally does not include an Alembic configuration. In an application where
Alembic is configured, generate a candidate with
`alembic revision --autogenerate -m "describe change"`, review its `upgrade()` and `downgrade()`
operations, and apply committed revisions with `alembic upgrade head`. Autogeneration is a draft,
not a substitute for reviewing data migrations, constraints, locks, and rollback safety.

> **Local-only database:** SQLite keeps the core exercise local; it does not replace the opt-in PostgreSQL dialect check in Lesson 07.

## Key concepts

- declarative base
- `Mapped` columns
- `select()` statements
- commit, rollback, close
- Alembic revision history and reviewed migrations

## Example

A support-ticket repository would receive a `Session`, add one record, and return a response model
rather than leaking its ORM entity. If the ticket table later gains a required column, change the
mapping and create a reviewed Alembic revision; do not rely on `create_all()` to alter an existing
database.

2. When must a session roll back?

4. Which value type represents money?

6. Why does `create_all()` not replace a migration history?
7. What must you review in an autogenerated Alembic revision before deployment?

## Done when

You can trace a request from a session boundary through commit or rollback and closure, and explain
how a reviewed Alembic revision moves an existing schema forward.
