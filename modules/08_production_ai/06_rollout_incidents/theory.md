# 06. Ограниченный выпуск и разбор сбоя

Практический вопрос: кандидат на G-01 отвечает быстрее, но одна версия ошибается именно в запрете ночного хранения. Другая не имеет метки по этому случаю; третья меняет схему так, что старый bundle не может читать данные. Перед таблицей решений сформулируйте, какие из `release`, `hold`, `reject` допустимы по заранее выбранному [протоколу](../02_releases_evaluation/theory.md).

**Интуиция.** Canary уменьшает долю реального трафика на новом release и позволяет сверять заранее названные сигналы; shadow отправляет копию входа кандидату, но ответ кандидата не показывают пользователю. Для G-01 опасно слепо shadow-копировать *действие*: побочный эффект reminder должен быть отключён или изолирован так, чтобы копия ничего не отправила. Ни canary, ни shadow сами по себе не создают репрезентативные метки качества.

```text
Canary: запрос → маршрутизатор → baseline (основная доля)
                           ↘ candidate (малая доля) → ответ пользователю

Shadow: запрос → baseline → ответ пользователю
             ↘ candidate → только наблюдение; external effects выключены
```

В [teacher walkthrough](../walkthrough.py) нет маршрутизатора и сервиса. Он принимает четыре уже существующих A case IDs и показывает локальные authored comparisons. Протокол был фиксирован **до** строк кандидатов: все четыре парные reference labels, ноль регрессий, critical `answer` обязателен, simulated p95 ≤30 ms, совместимый доступный bundle для rollback. `faster_critical_regression` имеет 20 ms и ошибочный `answer` → **reject**. `missing_required_label` имеет 20 ms, но `answer=None` → **hold_insufficient_evidence**. `compatible_complete_fixture` со всеми `True` и 20 ms → только **locally_eligible**. `incompatible_rollback` со schema 2 при прежнем reader `{1}` → **block_incompatible**. Данные авторские; это не результаты измеренной модели на незнакомой выборке и не реальный release. Упражнение [rollout decision](exercises/rollout_decision/README.md), ID `production-rollout-decision`, оставляет ученику алгоритм последовательных окон.

**Rollback — bundle и данные.** Для настоящего классификатора верните совместимые модель, preprocessing, schema и config. Для RAG также проверьте prompt, tools, corpus/index snapshot и права доступа. Откат бинарного кода не откатывает автоматически изменённые сохранённые записи. Существующий [`rollback_preflight`](example.py) проверяет только доступность artifact и возможность прежней версии читать stored schema; это необходимая локальная проверка, а не процедура восстановления production. Прежде чем увеличивать canary, проверьте контрольные группы, отклонения входа, технические ошибки, задержку, цену, наличие меток и конкретный план остановки. Canary по малой выборке не устанавливает статистическую надёжность или качество для всех пользователей.

**Один короткий инцидент на A `unknown_after_effect`:**

| Этап | Наблюдение и решение |
| --- | --- |
| T0 симптом | Run завершился `unknown_needs_reconciliation`; receipt отсутствует. |
| T1 сигналы | Trace A: один `tool_attempt`, результат `response_lost`. Привилегированный симулятор знает `effects=1`; внешний вызывающий процесс мог бы этого не знать. |
| T2 гипотезы | Сбой до эффекта **или** эффект уже случился, а reply потерян. |
| T3 различающая проверка | В **этой локальной fixture** `trace.result=response_lost` и `effects=1` исключают сбой до локального эффекта. `receipt=None`: удалённое подтверждение не проверялось и осталось неизвестным. |
| T4 ограничение ущерба | Для этого run выбран `hold`: автоматического повтора нет; владелец операции должен провести authoritative reconciliation прежде новой попытки. |
| T5 решение о восстановлении | Локально повтор не выполняется. Проверка старого bundle показывает reader schema 1 и доступный source artifact; совместимый откат технически допустим только для этой fixture. Remote recovery не проводился. |
| T6 последующая проверка | В A case осталось `attempts=1`, `effects=1`, `receipt=None`; второго эффекта нет в локальной записи. В операционном окне B по-прежнему `0/0` live quality labels, поэтому качество неизвестно. |

**Мини-runbook.** Зафиксируйте затронутые run/release IDs и окно. Остановите расширение canary или повтор действия с неизвестным результатом. Проверьте source, tool receipt и схему сохранённых данных; оцените обе гипотезы. Выберите containment и только совместимый recovery bundle, назначьте владельца действия. Затем повторно проверьте минимальные пользовательские сценарии и сигналы. Запишите причину, предел видимости и проверяемое предотвращение повтора без поиска виноватого. [Product study](../exercises/product_study/README.md), ID `production-product-study`, оставляет самостоятельный вывод о product evidence; [error budget](../exercises/error_budget/README.md) — другой контракт учёта окна.

Ошибка — объявить местный JSON `locally_eligible` сертификатом выпуска или автоматически повторить unknown operation. Самостоятельная вариация: после canary новая схема 2 уже сохранена, а прежний код читает только 1. Предложите различающую проверку и безопасный порядок containment/recovery; затем отдельно объясните, как поменяется решение при недостающих labels или более быстром, но худшем critical group.
